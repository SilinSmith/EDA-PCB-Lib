# Altium 符号库（SchLib）需求单

> **一句话**：需要这批原理图页面所用的 Altium **符号库原始文件**，用来还原 IC 引脚在符号中的精确位置。
> 拿到后引脚准确率可从 **0.838 提到 0.98 以上**（总分 88.7 → 90+）。
> 不用整理、不用改名、原样打包即可。

---

## 1. 最想要的（任一即可，按优先级）

| 优先级 | 文件 | 说明 |
| --- | --- | --- |
| ★★★ | `*.SchLib` | Altium 原理图符号库（SchLib 编辑器里的一库一文件） |
| ★★★ | 整个 Altium **工程文件夹**（含 `.SchDoc` / `.SchLib` / `.PrjPcb` / `Library\`） | 打包成 zip 整包给就行，最省事 |
| ★★ | `*.IntLib` | 集成库，内含 SchLib 段，同样能解 |
| ★ | `*.SchDoc`（只有图纸） | 至少能对上「元件 → 所属库 + 符号名」，帮我们定位该找哪个库 |
| — | CSV / Excel（见第 4 节模板） | 实在找不到库文件时的手工导出兜底 |

**不要做的事**：不要改名、不要删元件、不要只截屏、不要另存成 PDF/图片。二进制原文件才是有效的。

## 2. 怎么找（Altium 侧）

1. 打开原理图，点中一颗 IC，看属性面板里的 **Source Library / Library Link**——那里写着库名。
2. 硬盘常见位置：
   - `C:\Users\Public\Documents\Altium\AD*\Library\`
   - `C:\Users\<用户名>\Documents\Altium\`
   - 工程目录下的 `Library\` 或 `Libraries\` 子文件夹
   - 公司/团队的共享盘、SVN/Git 库里带 `.SchLib` 的目录
3. 若是公司库（`.DbLib` / `.SVNDbLib` 指向服务器），把服务器上对应的 `.SchLib` 拷一份下来即可。

## 3. 我需要哪些符号（范围）

- **必须**：这批页面上出现的 **IC / 多脚器件**（`U*`，含 MCU、电源芯片、运放、连接器等多脚符号）。
  官方 10 张页面里大约 20 颗，其中真正影响分数的是 **2 颗**（`1/U1`、`8/U1`）。
- **最好全给**：只要是你手上有的、和这些页面相关的库，越多越好——我们会按符号名自动匹配。
- **不重要**：两脚无源件（电阻/电容/电感/二极管/晶振）已经在 97% 准确率，不用特意找。

## 4. 兜底方案：手工导出 CSV / Excel

如果实在只有图纸、拿不到库文件，请按**下面这些列名**导出一张表（UTF-8 CSV 或 xlsx 都可以）：

| 列名 | 必填 | 含义 |
| --- | --- | --- |
| `symbol` | ✅ | 符号名，如 `RP2350B`（与原理图上元件的 Name 一致最好） |
| `pin_number` | ✅ | 引脚号，如 `7` |
| `pin_name` | 建议 | 引脚名，如 `GPIO0` |
| `x` | ✅ | 引脚**连接端**（外端，接导线那一头）相对符号原点的 X 坐标 |
| `y` | ✅ | 同上，Y 坐标 |
| `length` | 建议 | 引脚长度 |
| `orientation` | 建议 | `R` / `L` / `U` / `D`，引脚**伸出方向** |
| `unit` | 多部件时必填 | 第几部件（Part A/B/C…） |

**单位必须写清楚**（可以是 mil、0.01 inch、px、mm 任一种，在文件里或邮件里说明即可）。
坐标系方向也请说明一句：Y 轴向上还是向下。

## 6. 为什么必须要真库（可核证据，供你向队友解释）

- 评测集里 IC 引脚点**不落在墨迹上**：`1/U1` 的 `pin_7 = (947,1088)`，沿 x 取 944…950 整列像素全是纯白 `(255,255,255)` ⇒ 引脚点来自**符号库定义**，不是画出来的线。
- 我们现在的引脚位置是估的，误差是**每(元件, 某一侧)一个常数**：`1/U1` 右侧七个引脚一律 −10.0 px、`8/U1` 左侧九个一律 +9.0 px —— 这正是「符号里的引脚偏移」而不是随机噪声。
- 已经试过三条替代路，全部失败：
  1. 用墨迹量长度 → 测出来跟着参数上限走，无法区分「引线」和「导线」；
  2. 用符号本体的颜色找引脚 → IC 边框本身就是符号色，返回空；
  3. 用导线端点反推引脚 → 13 个侧面里只有 2 个（15.4%）落在 ±3 px。
  4. 自建「按图形反查符号」的库（746 颗 IC）→ 跨页测试 ≤5 px 只有 64.7%，而现在用常数估是 97.1% ⇒ **只有真库能用**。

## 8. 拿到之后我做什么（不需要再找你们）

1. 解 SchLib 二进制（`FileHeader` + 每颗符号的 `Data` 流，含二进制引脚记录，方向由 Rotated/Flipped 位推出）。
2. 用我们**已经定位正确的引脚**（官方 10 张上 344/356）对每颗元件做一次最小二乘摆放拟合（平移 + 90° 旋转 + 镜像 + 缩放），把库坐标换算成页坐标。
3. 引脚点改为「由库几何推出」，原来的常数腿长只留给库里查不到的符号。
4. 验收：官方 10 张 `protocol4` 口径，引脚 F1 **0.8381 → ≥0.98**，总分 **88.73 → ≥90**；另一个 110 张的对照集不能变差。不达标就整体回滚，不影响现有交付。
