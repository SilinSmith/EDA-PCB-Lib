# 失分动画（`loss_case6.mp4` / `.gif`）

一个真实比赛样本（官方 10 里的案例 6）从「检出」到「和 GT 对账」的全过程，用来解释导线轴到底漏在哪。

| 时间 | 画面 | 说明 |
|---|---|---|
| 0–2 s | 整页 | 案例 6，2186×1110 |
| 2–7 s | **元件框选** | 我们检出的框逐个亮起（粉 = box / IC，蓝 = 其余），带检出序号 |
| 7–14 s | **导线蔓延** | 每张网从起点沿相邻端点 BFS 蔓延，颜色 = 网络编号，右下角计数 `已画 n / 共 86 段` |
| 14–18 s | **对账** | 灰底压暗，蓝 = 我们画的线；绿 = GT 线段且端点误差 ≤5px 判对上；红 = GT 有、我们没对上 |
| 18–21 s | **放大典型漏法** | 一条蓝线穿过结点继续往下，GT 却在结点处断成两段（红圈标出 GT 端点） |
| 21–22 s | 小结 | 86 段 GT 导线配上 49 段，其中 33 段「被我们画长了」，只有 2 段是真没画 |

结论：这一页的导线轴失分**不是没检出线**，而是**没有在 T 型结点处断开**。GT 的每段导线止于结点，
我们把整条通路当成一条线段画下来，于是判分时「两端点各差 ≤5px」这一条永远不满足 —— 一条长线会同时判错
GT 的两段。这正好对上全局统计：GT 有 T 型结点 166 个，我们只识别出 70 个。

补充（§5.397.11）：即使断点位置**一个不差**（oracle 直接用 GT 自己的边端点断开），官方 10 张也只涨
**+0.42**，所以这条轴已封口 —— 动画是用来说明机理的，不是待办。

生成脚本：`work/_anim.py`（`--pick` 选案例，`--case N` 出片）。

## 引脚腿长动画（`pin_leg.mp4` / `.gif`，15.4 s，308 帧）

引脚轴唯一的残差——**脚点差 9~20px**——到底是怎么来的。五幕：

| 时间 | 画面 | 说明 |
|---|---|---|
| 0–2.2 s | 案例 1 整页 | 绿 = GT 脚点、蓝 = 我们发出的脚、粉框 = 我们检出的元件 |
| 2.2–5.6 s | 放大 U1 右侧 | 7 根脚**全部偏 (10.0, −0.9) px**，红箭头 = GT−我们 |
| 5.6–9.0 s | 像素级（INTER_NEAREST） | 框边 → 我们的脚(腿 10px) → GT 脚点(腿 20px) 三点落在**同一条连续黑线**上；下方柱子是同一 y 行最暗像素，从框边一路全黑、中间没有空白 |
| 9.0–12.4 s | 案例 8 U1 左侧 | 9 根脚全落在一个固定偏移上（纵向恰好差一行脚距） |
| 12.4–15.4 s | 小结 | 三层事实：GT 脚点来自符号库 / 我们的脚也全在框外 ≤15px / 但腿的外端在图上不可测 |

一屏一句话：**GT 的脚点在「符号库引脚外端」，而这个外端在渲染图上与它接的导线同色共线、没有断点**，
所以不是参数没调好，是这类信息 PNG 里不存在。把腿长常数从 12/10 改到 20/21，引脚只挪 2px
而脚号绑定崩掉，整条管线 89.99 → 82.64（§5.391）。

生成脚本：`work/_anim_pin.py`（`--still` 只出静帧）。

生成方式（两个脚本都只是加了路径参数，默认行为不变）：

```
python -X utf8 work\_anim.py --case 12 --gt-root work\_new2026\open_GT-1020\open_GT ^
       --pred work\_cv_run_vote0\final_results --prefix loss_case
python -X utf8 work\_anim_bind.py --case 11 --dir work\_cv_run_vote0 ^
       --gt-root work\_new2026\open_GT-1020\open_GT
python -X utf8 work\_grab.py eda-pcb\docs\media\loss_case12.mp4 150 work\_frame.png   :: 抽单帧核对叠加层
```

一屏一句话：**这几页丢的分都能在图上指出来** —— 12 是端口符号与网的成员划分、11 是叠画符号没切开、
1 是位号行内重绑、13 是三脚 box 件漏检；不是「模型差一点」，每一处都有对应的机制缺口。
