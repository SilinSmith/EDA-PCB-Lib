这张图上最要紧的三个数

  • 官方 Q&A（2025-10-04）把评分口径整个换了。评测 Q2 原文：「非 box 类型元器件 pin name, pin number 不参与评分」——之前撑起 pinF1 的那 2808 个 tp（r/c/l/gnd 的图章引脚）一分都不算，唯一算分的只有 IC（GT 里 9320 个 box 引脚），我们现在 tp 36。
  • 评测 Q5 原文：「Vcc和gnd是∅，直接是坐标匹配」，Q6：「GND的序号名字不影响评分」。所以 ∅NNN 根本不需要被推导出来——它靠 bbox 匹配。这一条直接把 ComponentF1 从 0.1542 抬到 0.5225。
  • 数据 Q6 原文：那些 119/115/202 的引脚号 「编号是随机生产的」。这也解释了为什么 net_hypergraph 的 P 只有 0.3282——兜底键元件的引脚号天然对不上，必须在 net 引用里剪掉。

已经在起作用的关键旋钮

  • DROP_UNKEYED=0 —— 没读到位号的元件照常输出（键用 pNNN 兜底），靠坐标去配 ∅：+5.61 分（component tp 1747→5077）。
  • NET_DROP_UNKEYED=1 —— 只把兜底键元件的引用从 net 超图里剪掉，不剪 component：+1.79 分（netH F1 0.1357→0.1862，P 0.1328→0.3254）。
  • --texts both —— stage1 与 textseg 两版切法都留着（merge_boxes_both，BOTH_TOL=0.65），交给 assign 打分去选：+0.59 分（union 22.9068 → both 23.5009）。这是默认值。
  • canon_designator 的形近数字纠正（Rl4→R14）—— 新增 _FIX_DIGIT，前缀贪心对不上时退一步把尾部当数字重解：连同下面两条 +0.167（23.5009 → 23.6682）。
  • fit_value 拒绝位号形状（C5/R14 不再被 NETNAME_RE 放行当值，+0.138 里的一部分）。
  • VALUE_NETNAME=0 —— 关掉「网络名当值」（VCC/Vout/SDA1 不再顶替真正的值）：+0.029（tp 5224→5232，text_mismatch 969→961）。
  • BOX_PIN_PARTIAL=1 —— box(IC) 的引脚号从「一个读废、整颗作废」改成逐引脚回退：+0.288（pin tp 36→69、netH tp 3438→3475、line tp 553→578，component 一个数都没动）。这是当前唯一算分的引脚项（官方评测 Q2）。
  • ✗ 反例 --texts multi（把「紧框 + 外扩框」两份裁片都留给 assign 挑）实测是负的：23.0447 vs both 23.5009，墙钟还翻倍。机制：assign 的选择还发生在全局位号去重与跨元件抢读上，多出来的裁片会去抢别的位置 —— 候选池不干净时「让打分器挑」不成立。
  • FREE_STEAL=1 —— 自由文字（d > FAR=40）也进位号「抢读」池：+0.37 分（大 IC 的位号印在框外，过去谁都不要）。
  • VALUE_LIKE 门控 —— r/c 的值不含字母/Ω/μ 就写 null：+0.72 分。
  • STEAL_R=80 位号抢读 +0.19、VALUE_STEAL_R=40 值兜底 +0.08、PREFIX=strict 前缀矫正。
  • ✓ 本轮最大的一项 VLM 补强（eda-pcb\vlm\）：reasoning_effort:"none"（关思维链的唯一有效开关）之后，同一个裁片上 VLM 比 CRNN 高 +0.25。四条通道各自的独立增量：位号改名 +0.012 ｜ 逐引脚号/名（每个引脚点裁不对称窗口 + 打红圈 + 8 格拼网格，编号 0.970 / 编号+名称 0.864）+0.55 ｜ 「值」（读 位号=值 一整行，只采纳「自报位号 == 元件键」的读数）+0.949 ｜ IC 器件型号 → Name（1021 次调用）+0.541。另外值通道顺手捡位号（只对 pNNN 兜底键生效，零额外调用）再 +0.369。component F1 0.5225 → 0.5882、tp 5232 → 5846。
  • ✓ 本轮新增三项 ①textrec\infer.py CTC 解码没按 w//8 截断：read_many 批内补白到本批最大宽，双向 LSTM 会把补白也解码成尾字符（R2 → R2441、C4 → C44），539 个框里 85.7% 与逐条读不一致；按 w//8 截断后 220 张端到端 +0.44（23.8329 → 24.3976，隔离口径 +0.565）。②兜底键补读位号 desig_fallback：pNNN 键永远不可能和 GT 对上，对它补读位号有赚无赔；③DESIG_PROMPT 原本是给 IC 写的（开头「这是…一个元器件（IC / 模块）」），模型看到一颗电容就回 NONE（C6/C16 全废）——新增 PASSIVE_TYPES / DESIG_PROMPT_PASSIVE 后同一批元件读出 C6✓C16✓TP1✓TP2✓，+0.576（24.5185 → 25.0946）。三项叠加：端到端 26.3344 → 27.3264。
  • ✗ desig_all（给所有元件重读位号）再次判负：25.0823 < 25.0946，且 desig_calls 4091→6788、墙钟 768 s→2646 s。原因固定——把本来就对的键重读一遍，读错的会把对的改坏。只补兜底键，不要动已有键的元件。
  • ⚠ 已被口径作废：PIN_STAMP=1 当初量到 +4.90 分，但它的收益全在非 box 引脚上，现在一分不算（box 引脚 tp 只从 22 变成 36）。
