## 1. 这不是「再加一个去重」——它是标尺的规定

`eda-pcb\schematic_parser\metrics.py:288 assign_components(gt, pred, cfg, detail=None)`：

1. `:311-314` **按键配对** —— `set(gc) & set(pc)`，同名位号直接成对；
2. `:324-363` 剩下的做坐标匹配，用的是 `:258 _assign(cost)` 的**匈牙利一对一**；
3. `:366-383` 逐对判 type / `bbox_ok` / `component_text_ok`，不满足 ⇒ **`fp += 1` 且 `fn += 1`**。

每个 GT **至多配一个预测**，多出来的主张者一律记 fp。所以「一个东西只归一个人」
不是我们的选择，是标尺的规定。

**重要口径更正**：`bbox` **不驱动匹配**（`schematic_parser\stamp.py:9-16` 的注释写明
「bbox 不用于 component 匹配，只在 key matched component 上计算坐标误差，默认 20px」）。
此前 `work\tools\eval\fn_fp.py` 用 `corner_dev <= 20` 当**匹配**判据做出来的 FN/FP 表，
是**我自己的诊断口径，不是官方口径** —— 那张表里的 FP 数**不能**用来衡量模型好坏。

## 2. 为什么原来的 IoU-NMS 不够

`stamp.snap_box`（`schematic_parser\stamp.py:88`）把同类框都换成**同一个正方形**
（以原框中心为中心）：`c`/`r`/`gnd`/`d`/`led`/`pin`/`testpoint` = **20px**、`v` = 10、
`net_input`/`net_output`/`net_bidirection`/`amp_3pin` = 30、`l` = 34。

两个 20×20 的框**中心差 10px** 时，IoU 只有 **0.33** —— 标准的 IoU-NMS（0.45/0.7）
完全不抑制。可它们显然在抢同一颗符号。**IoU 在小图章上是个坏尺子**：
判分容差是 20px corner，而 IoU 是按面积比算的。

## 3. 实测口径（决定阈值）

`work\tools\diag\_owneval.py`：19 张快测集的 **stage1 产物**（`work\_submit_out220r36\runs\stage1`），
取所有**同类型**框对，量 `cd = max(|dx|,|dy|)`（贴章后 = 官方 `corner_dev`）、
`side = min(两框 min(w,h))`、`frac = cd/side`；真相判据是
**「两框各自的最近同类 GT（corner_dev ≤20）是不是同一颗」**。

> ⚠️ **这张表只作参考，不能当判据** —— 见第 6 节：它的真相代理在密集排布下会退化，
> 报「`cd<=12` 误伤 0」是**假的**（端到端实测在 `0103` 上误伤 2 颗真 GND）。

**共 3975 对同类型框对：**

| 判据 | 并掉 | 真重复 | 误伤真符号 | 误伤率 |
|---|---|---|---|---|
| `frac<=0.3` | 0 | 0 | 0 | 0.0% |
| `frac<=0.5` | 3 | 2 | 1 | 33.3% |
| `frac<=0.7` | 8 | 4 | 4 | 50.0% |
| `frac<=1.0` | 29 | 6 | 23 | 79.3% |
| `cd<=8` | 0 | 0 | 0 | 0.0% |
| **`cd<=12`（默认）** | **2** | **2** | **0** | **0.0%** |
| `cd<=20` | 46 | 25 | 21 | **45.7%** |

按类：`gnd` 1136 对（**99.6% 是不同 GT**）、`r` 921（99.9%）、`c` 914（100%）、
`v` 352（100%）、`switch` 351（89.7%）、`box` 209、`d` 57、`l` 11、`net_input` 11、
`mosfet`/`net_output` 各 6、`led` 1。

**结论一：官方那 20px 是「框算不算对」的容差，不是「是不是同一颗」的半径。**
拿它当并框半径，`0092` 的电阻阵列 R1..R20（彼此只差 **16.3~16.6px**、`frac` **0.82~0.83**，
两两都是**不同** GT）会被整排并成一堆。按 20px 在**提交文档**上再去一次重
（`work\tools\diag\_dupscore.py`）：19 张 **35.438 → 35.188 →（再去引脚）35.065**，
净 **−0.373**，其中 `0042` 一张掉 **−4.87**。

**结论二：`frac`（中心距 / 自身短边）比绝对像素好** —— 它自动跟着类别尺寸走
（`v` 的 10px 和 `net_input` 的 30px 不是一个尺度）。但它单独也不够：`0092` 那排
在 `frac` 0.83，所以阈值必须**紧**。

**结论三（已推翻）**：按上表看 `cd<=12` 像「有收益、无风险」的那一档（并 2 对、误伤 0），
它正好就是 `stage1/detect.py:53` 早就写着的 `DEDUP_PX = 12.0`（原来只用在**跨来源**判同上）。
**但 19 张端到端实测把它否掉了** —— 那 2 对在 `0103` 上是**两颗各自独立的 GND 符号**，
并掉就是丢 2 个 tp。见第 6 节。

### 顺带纠正一条旧结论

早前子代理报的「497 个 FP 里 ≥255 个是同一颗器件被重复检测」，
**是检测器原始输出上的现象，不是提交文档上的现象**：
* `_dupscore.py` 量到 19 张里 **17 张一个元件都没丢**（流水线本来就去重了）；
* `_owneval.py` 在 stage1 产物上量到，真正**同 GT** 的近重复只剩 25 对 / 3975 对；
* 真正凭空造出来的 FP 只有 **50/497 = 10%**。

⇒ 那张 FN/FP 表是用 `conf 0.05 + ultralytics 默认 NMS + 未贴章` 跑的，
和流水线实际使用的配置（`conf 0.25` + 我们自己的 `NMS_IOU=0.5` + **贴章后再压一次**）
不是一回事。**不要再引用它的 FP 数当模型精度。**

## 4. 落地：一个实现，三处接线

### `eda-pcb\cvparts\own.py`（新，本模块）

```
Party(id, box, kind, score, meta)          # 一个主张者
contenders(a, b, frac, floor_px, same_kind)
thin(parties, frac, floor_px, same_kind, rule, ledger) -> List[Party]
assign(claimants, items, gate, cost, ledger, rule) -> ({claimant_id: item_id}, ledger)
legacy_thin(parties, px=LEGACY_PX, ledger)  # 绝对像素版，= cd<=12
```

旋钮：`OWN_FRAC=0.30`、`OWN_FLOOR_PX=0.0`、`OWN_LEGACY_PX=12.0`。

**三条不变式**（`python eda-pcb\cvparts\own.py` → 自检 **14/14 通过**）：

1. **一对一** —— 一个标的至多一个主人，一个主张者至多一个标的；
2. **有账** —— 每次判负都记「谁、输给谁、差多少、按哪条规则」，原始分数与框都留着；
3. **单调** —— 阈值放宽只多并，不造出新东西。

**一个刻意的不变式**：**链式相邻不传递合并**。`q0..q3` 两两间距 4px，但 `q3` 离 `q0`
12px（> `0.5×20`）⇒ `q3` 幸存。如果做传递闭包，`0092` 那种 16.5px 间距的电阻阵列
会被整排吃成一个。自检里专门有一条守着它。
