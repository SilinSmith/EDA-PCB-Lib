# 公开 40 张 box 引脚损失链审计（2026-10-08）

固定原始 public40 上，baseline 与 `a15fb9f` 的 box 引脚 TP 都是 **32 / 1492**，平均 pin F1 都是 **0.062317**。a15 的主要收益来自网络端点映射；这 40 张图的 box 引脚没有新增 TP。总分 23.1241 → 23.7290 不能解释为 box 引脚已经改善。

本报告只审计原始 `public-validation40-manifest.json` 对应的 40 张图。原 verification20 已转为开发数据；此审计没有读取或评估新 verification20 标签。本次未使用赛方评测程序，实际得分使用仓库内按题面/Q&A 重建的 `schematic_parser.metrics`，没有改动评测口径。

## 2. 逐层定位，不把几何关联当得分

为辨别上游原因，另做只读诊断关联：GT box ↔ stage1 框采用一对一匈牙利匹配，候选满足四个 bbox 数字误差均 ≤20 px **或** IoU≥0.5，优先 box 类型；GT 引脚 ↔ 该框的 raw 接点分别采用 ≤5、≤12 px 的一对一匹配。选取 raw 读数时优先 ≤5 的匹配。

这不是模型获得的新身份或新引脚，也没有回写预测。IoU-only 框、GT 几何关联和 12 px 门限只帮助说明现象，不能替代正式匹配规则或声称可恢复的得分。5/12 两组独立匹配有 13 个引脚使用不同 raw 索引，完整审计保留两者，避免隐藏关联歧义。

框覆盖为：146 个 GT box 中，141 个严格 corners20 覆盖、4 个仅 IoU 覆盖、1 个未关联。未关联的是 `public_0003/U5`，GT bbox 的 y 下边界为 -35，包含 2 个 GT 引脚；不能仅凭这一项把它认定为正常元件漏检。

按局部框是否得到 GT 身份，42 个 box /584 个引脚身份一致；99 个 box /875 个引脚的 GT 键不存在；5 个 box /33 个引脚的 GT 键存在但落在另一个框上。下面采用“从上游到下游的第一个失败”互斥分类，TP 优先：

| 第一处失败 | baseline | a15 | 解释边界 |
|---|---:|---:|---|
| 框未关联 | 2 | 2 | 包含上述越界 GT 框 |
| 局部身份缺失或错误 | 906 | 906 | 可能是读取/分配错误，也可能是转换标签的位号不在图上 |
| 已有正确身份，但没有 raw 接点 ≤12 px | 293 | 293 | 接点不足、定位过偏，或 GT 点定义差异尚需看图 |

## 3. 四个确证的重复号码代表问题

冻结默认装配政策逐 raw 索引模拟，与两臂缓存 pinindex 的保留/丢弃结果 **零差异**。以下 4 个目标点、号、名均满足当前评分条件，但较早的同号读数先占号；它们的较早代表都有名字。

| 图 / GT 引脚 | 当前较早代表：号置信 / 名字置信 | 后来的正确代表：号置信 / 名字置信 | 正确点与 GT 距离 |
|---|---|---|---:|
| 0129 U1.2 | raw2：2 .99957 / R1 .51263 | raw3：2 .99859 / 2 .99901 | 3.63 px |
| 0077 U12.8 | raw1：8 .47458 / VOUT .95266 | raw5：8 .96372 / GND .99204 | 1.80 px |
| 0077 U13.1 | raw3：1 .57597 / F .92834 | raw8：1 .99981 / VIN .98875 | 4.41 px |
| 0160 U19.5 | raw3：5 .70607 / EN .97011 | raw5：5 .98060 / LX .89153 | 2.00 px |

实际 PNG 肉眼核对：0077/U12 的 VOUT 外侧打印 6，GND 打印 8；0077/U13 的 FB 外侧打印 6，VIN 打印 1；0160/U19 的 EN 外侧打印 6，LX 打印 5；0129/U1 打印连接器数字 2，较早代表绑在上一行，后来读数对应目标点。前三处清楚显示较早号码为误读，不是 GT 几何为运行时提供答案。

按号码置信选择重复代表，在后三例会选择正确读数；0129 的较早错误代表反而有略高号码置信，需要名字质量或文字框/接点归属证据。仅凭这 4 例不能保证某个通用排序政策的净收益，必须用实际缓存装配重新评分，并检查其它 TP、FP 和网络。

两臂合计还发现 216 个“较早无名读数先占号”的 raw 事件，a15 为 108 个。**其中没有找到同时号码/名字正确、点 ≤5 px、局部身份正确的直接恢复 TP**；不能把这一机制本身的事件数称为可恢复引脚数。

## 4. GT 保真度：三个反例和五个可读对照

逐引脚报告把未看图的元件保持为 `not_visually_inspected`。以下是有目的的小规模抽检，不能用它估算整个 40 张或 906 个身份损失的噪声比例。

| 图 / GT 元件 | 实际 PNG 观察 | 能得出的结论 |
|---|---|---|
| 0003 / U4 | 型号 TXB0108PWR 上方印的是 **U?**，不是 U4 | OCR 无法从这个占位符读出转换后 U4 |
| 0031 / U1 | 全图只有型号 LTC695-3.3、LT1129-3.3、功能名/引脚名等，无 U1 位号 | 这个 GT 身份不是从打印 U1 恢复的任务 |
| 0048 / U1 | 全图为未编号的应用电路，IC 内印 VCC/VSEN/IBUS/COMP1/COMP2/DRV/ISEN/VDD/GND/CF，无 U1 | 不能将该项直接归因于位号 OCR 漏读 |
| 0087 / U23 | FPGA 框内清楚打印 U23 和 XC4003/PQ100 | 图上存在可观测身份；它的具体失败仍需逐项定位 |
| 0129 / U1；0077 / U12、U13；0160 / U19 | 图中均打印相同 GT 位号，目标号码可读 | 支撑上一节的真实重复读数问题 |

旧报告 [GT保真度与位号上限](GT保真度与位号上限.md) 提供派生标签重编号的历史证据，但其旧档样本、VLM 抽检及“约八成不可赢”估算**不直接适用于当前固定 40 张**。也不能只凭“同前缀”或“键在 GT 中”就把标签宣称为已经清洗验证过。

1492 个 GT 引脚中有 191 个非纯数字号码、355 个名字等于号码。它们包含可能真实的字母编号，也包含需要看图核实的转换/OCR 字串。这两个总数同样不是装配放宽后的可恢复得分；只读机会探查和实际缓存变体另有记录。
