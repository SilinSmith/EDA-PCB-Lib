## 1. 网络分（权重 0.35，最大的一块）

### 1.1 官方口径的机制（决定了能从哪里下手）

`metrics.py:497-519` + `data.py:147-149`：

- `net_pin_set(net)` = `parse_hypergraph(net['hyperGraph'])`
  ⇒ **网络成员只看 `hyperGraph` 这个字符串**（`"(U1.7,U1.8,U3.1)"`），**与 `pins` 段无关**。
- `match_nets`（`:477`）对全部 pred/GT 网络做一次匈牙利匹配，相似度 = 引用集合交集的
  大小（+ Jaccard 微项），**没有门限** ⇒ 有几条 pred 网络就有几对配对。
- `tp = Σ|p_set ∩ g_set|`（配对上的网络**共享的引用条数**）
  `fp = Σ|p_set| − tp`，`fn = Σ|g_set| − tp`。

⇒ 网络分只由两件事决定：**① 我们发出的 `(元件, 引脚号)` 引用有多少条是对的；
② 发出的条数够不够（召回）**。**网络的名字完全不参与打分。**

### 1.2 220 张实测

```
GT   10745 条网络 / 22546 条引用（均 2.1）
我方  4616 条网络 /  7876 条引用（均 1.7）
匈牙利配对 4560 对
tp 3398   fp 4478   fn 19148   ⇒ F1 0.2234
```

**GT 的 22546 条引用，我方处在哪一步：**

| 分类 | 条数 | 占比 | 含义 |
|---|---|---|---|
| **A 发出来了而且对** | 3398 | **15.1%** | 唯一的得分来源 |
| **B 料齐了但没进这条网络** | 1228 | 5.4% | 元件键与引脚号我方**都有**，只是没被放进配对上的那条网络 |
| **B' 料齐了但网络没配上** | 594 | 2.6% | 同上，且整条 GT 网络没被配对 |
| **C 有元件、没这个引脚号** | 7630 | **33.8%** | 引脚识别问题 |
| **D 连元件键都没有** | 9696 | **43.0%** | 位号/元件匹配问题 |

**网络规模分布（0/1/2/3/4/5/6+ 条引用）：**

```
GT    [   4, 3600, 4892, 1229, 492, 243, 285]
我方  [   0, 3454,  600,  228, 115,  53, 166]
```

⇒ **我方 4616 条网络里有 3454 条（74.8%）只连了一个东西**；GT 只有 33.5% 是这样。
GT 的双引脚网络有 4892 条（45.5%），我方只有 600 条（13.0%）。
**这是「连接不足」的直接指纹**：我方只发出 7876 条引用，是 GT 的 35%。

### 1.3 天花板（注意 B 类是**神谕**，不是可达增益）

- 只把 B/B' 搬到位：F1 0.2234 → **0.3065**（+0.083 ⇒ **+2.9 分**，按 0.35 权重）
- 再把 C 修好（B+C）：F1 0.2234 → **0.5210**（+0.298 ⇒ **+10.4 分**）

⚠ **但要清醒**：B 类的定义里隐含「GT 网络已经和我方某条网络配上了」这个信息，
而 B 的样例（`0001 net_8` 缺 `C5.2`/`R7.1`，配上的 `net_44` 里只有 `R8.1`）
说明我方那条网络里装的是**别的元件** —— 要把 `C5.2` 放进去等于知道答案。
所以 **B 是上界，不是可实施的路线**。

**配对网络里我方多出来的引用 4419 条**（= fp 4478 的 98.7%）：
我方在配上的网络里的精度 = `3398/(3398+4419)` = **43.5%**。

## 2. 引脚分（权重 0.25，F1 只有 0.0018 —— 最大的绝对缺口）

官方口径 `metrics.py:426-464`，四关全过才算 tp：

1. 元件键配上（`:311 set(gc) & set(pc)`，**精确字符串**）
2. 引脚号配上（`:442 out[(comp, pin_key_to_number(pk))]`）
3. `pinname` **逐字相等**（`:455`，不等就 `fp+=1; fn+=1`）
4. 点距离 ≤ `cfg.pin_tol`（`:460`，**5.0 px**）

### 2.1 四关漏斗（220 张，分母 = GT 引脚 9356）

```
GT 里 box 元件 996（有引脚 981 / 无引脚 15）
其中有引脚的元件里，我方一条引脚都没有的：615  = 62.7%

② 号没配上          8273   88.4%
② 号配上            1083   11.6%
   ③ 名不等           730    7.8%
   ③ 名相等           353    3.8%
      ④ 位置超差      175
      ★ tp           178    1.9%
我方多出来的号(fp)   689
```

**②关失败的两种形态（修法完全不同）：**

| | 元件 | 承载 GT 引脚 | 占比 | 其中号配上 |
|---|---|---|---|---|
| (a) 我方整组引脚都没发 | 615 | 5210 | **55.7%** | 0 |
| (b) 发了引脚但号对不上 | 366 | 4146 | 44.3% | 1083（26.1%） |

(a) 的 5210 **逐位等于** `_desigcand2.py` 量到的「没配上的 GT IC 引脚数」
⇒ (a) 本质是**元件键错了**，引脚归到别的键上去了。

### 2.2 第③关（名）**不是格式问题**

- 「归一化后相等」（去掉所有非字母数字再大写）只占③失配的 **0.5%**（4/730）
- 「两边都空」 0 条
- 最常见的失配组合：`FB → F`(10)、`3 → 2`(8)、`GND → 1`(7)、`GND → 4`(7)、
  `VIN → 1`(5)、`1 → A`(5)、`2 → GND`(5)、`VOUT → 2`(5)
  ⇒ 是**读串了行/读到了别的文字**，不是分隔符差异。

### 2.3 第④关（位置）**纯几何救不回来**（`_pinsnap.py`，n = 353）

以「三关全过、只剩④」的 353 条引脚为样本，逐个候选变换量 tp：

| 变换 | tp | 占 |
|---|---|---|
| T0 原样 | **178** | 50.4% |
| T1 吸附我方元件框边 | 8 | 2.3% |
| T2 吸附真值元件框边（上界） | 5 | 1.4% |
| T3 吸附我方框边 + 外扩 2/3/4/6/8 | 33/66/105/147/176 | 9.3/18.7/29.7/41.6/49.9% |
| T4 沿「框中心→点」推到框边 | 3 | 0.8% |
| **T5 全局平移扫描 dx,dy ∈ [−4,4]** | **最优 (0,0) = 178** | — |

⇒ **真值引脚点根本不在元件框的边上**（否则 T1/T2 会涨），而且**不存在任何常数偏移**
（全局扫描的最优点就是恒等变换）。T3 外扩到 8 也只是**逼近恒等**而已。

超差的 175 条 = **近失（5 < d ≤ 12）107 条 + 远离（>12）68 条**：
一半是围着 5px 门限的抖动，一半是引脚身份完全错（样例 `d=265.7`、`d=357.7`）。

## 3. 位号（同时是网络 D 类 43.0% 与引脚 (a) 类 55.7% 的根）

### 3.1 「修选择」的天花板 = 3.6%（`_desigcand2.py`，220 张）

没配上的 GT IC **629 颗 / 5210 引脚**（GT IC 共 996 颗 / 9356 引脚）：

| 分类 | 元件 | 引脚 | 占引脚 |
|---|---|---|---|
| R0 连重叠的我方元件都没有 | 50 | 623 | 12.0% |
| **·候选表是空的** | 418 | 2915 | **56.0%** |
| **·有候选但全错** | 152 | 1484 | **28.5%** |
| **★ 候选表里**有**正确位号** | 9 | 188 | **3.6%** |
| 只差大小写（GT `u2` vs 我方 `U2`） | 4 | 82 | 1.6% |

⇒ **在融合层重做「候选打分/选择」最多只能拿回 3.6% 的缺失引脚。**

### 3.2 「模糊/家族修复」是**幻觉**（`_desigmatch.py`）

有候选的 210 颗里，「最近候选」与 GT 键的编辑距离看着很美：

```
d=0  18 (8.6%)   d=1 115 (54.8%)   d=2 48 (22.9%)   d≥3 29 (13.9%)
```

但样例拆穿它：`U4 → U1`、`U2 → U32`、`U1 → U13` —— 短位号（`U\d`）之间的
编辑距离**天然就是 1**，这些是**完全不同的元件**，不是形近误读。没有可用信号。

### 3.3 ★ 但错候选里有一半是**关联错**，不是识别错

对有候选的 210 颗：

| 判定 | 颗数 | 占比 | 含义 |
|---|---|---|---|
| **候选 = 同一张图里另一个 GT 元件的正确键** | **101** | **48.1%** | 字读对了，**挂到了错的元件框上**（关联/框边界问题） |
| 候选不在任何 GT 键里 | 109 | 51.9% | 真的读成了另一个形状（识别问题） |

差异形态：`字母同、数字不同` 121（57.6%，其中 101 属于上面第一类）、
`字母都不同` 31（14.8%，如 `XOSC1 → U28`、`OUT10 → U5` —— 网络名被读成位号）、
`只差大小写` 22（10.5%）、`数字被少读` 19（9.0%）、`数字被多读` 17（8.1%）。

⇒ **这是本轮唯一一个「病因明确、且不在识别器内部」的新线索**：
约 101 颗 IC 的位号文字是对的，只是**归属的元件框错了**。

## 5. 结论：所有指标都汇到同一处

| 指标 | 权重 | 当前 F1 | 融合层可修 | 真瓶颈 |
|---|---|---|---|---|
| net_hypergraph | 0.35 | 0.2234 | B 类 8%（**神谕**，不可达） | **D 43% 元件键 + C 34% 引脚号** |
| component | 0.30 | 0.5946 | 剪虚警 ≈ +1.0 分 | 漏检/虚警 |
| pin | 0.25 | 0.0018 | **0%**（几何已穷尽） | **(a) 55.7% 键错 + (b) 引脚号/名读错** |
| net_line | 0.10 | 0.0312 | 只在配对上的网络里数边 | 同上 |

**能改写分数的只有两件事：让元件键对，让引脚号/名对。这两件都在 stage2
（检测 → 文字关联 → 识别），不在融合层。**

融合层（`eda-pcb\fusion\`，10 个文件）本赛季已做到：
- 读数优先三闸（`solve.gap_fill` / `priors.run_inwindow` / `llm_judge.agree_prior`）
- 读数形状闸（`priors.desig_shape_ok`，砍 `USB_D+`→`U580` 这类伪位号）
- 裁切方向反馈（`cropfix.py`）、现实规律判断（`audit.py`）
- 两个真 bug 修复：`cvparts\hypo.py` 的 `Slot.add` 合并后不重排、
  `fusion\claims.py` 的 `_add_vlm` 用 `pool.best()` 去重（会丢掉更强的 VLM 证据）

⇒ 融合层已经**安全**（22.9943，不制造幻觉、不掉分），但**它已经接近自己的天花板**。

## 6. 下一步的建议（按性价比排序）

1. **元件框 ↔ 位号文字的「再归属」**（唯一的新线索，见 3.3）
   - 目标：那 101 颗「字对、框错」的 IC。
   - 已有素材：`stage1` 的 `components[].bbox_json`、`texts[]`（539 个框，**不含字符串**）、
     `_assigned\<case>.json` 的 `comps[cid].designator` 与 `desig_slots`（含 per-cid 候选与 `score`）。
   - 缺的：**未被认领的 210 个文字框（`n_free`）没有 dump**，而它们正是「挂错」的候选来源。
   - 代价：要么改 stage2 把 `n_free` 的框与识别结果写出来（重跑 stage2），
     要么在融合层对这些框重新调 TextEngine 读一遍（本地模型，成本可接受）。

2. **剪虚警**（稳定 +1 分左右，风险低）
   - 9 张上 `component.extra 91`、`net` 配对网络里 4419 条多余引用。
   - 可以对「元件框几乎重合、键不同」的重复检测做合并，但要小心别把真元件也合掉。

3. **引脚号的召回**（潜在最大，但最难）
   - `(b)` 类 366 颗元件里 GT 引脚号只配上 26.1%，且 `(a)` 类 5210 条引脚连组都没发。
   - 这需要 stage2/VLM 的引脚读取（`vlm\enrich.py` 的 `read_pins`）改进，
     而 `_pinfunnel` 的第③关显示**读串行**是主要失效模式 ⇒ 取景/分行要动。
   - 建议先只在 `work\tools\eval\fast.py` 的 19 张回归集上试，别直接上 220。

4. **不要再做的**（已量死）：
   - 融合层位号候选重打分/选择（≤3.6%）
   - 位号模糊/家族修复（编辑距离无信号）
   - 引脚点几何吸附/平移（0%）
   - 墨迹尺度归一（除非连模型一起重训，见 `尺度归一_诊断.md`）
