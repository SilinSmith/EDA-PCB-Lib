# 大一统交叉校验层：实装说明（`cvparts/unified.py`）

> 用户 m50175：「我希望的是一个『大一统』的交叉验证机制，这需要你泛化当前的各个交叉验证接口，
> 然后还要提供各种各样的支持，比如说对应的高效中间过程的数据结构。」
> 本条 = 该需求的**实装**；决策前的全仓盘点见 `docs/reports/统一校验与裁决层_侦察报告.md`
> （45 条交叉校验清单 + 5 种并行候选表示 + 统一 API 提案 + 网络成员决定链）。

## 1. 一句话

全仓原本有 **5 种互不兼容的候选池表示**、**5 套重复的证据分数字典**、**6 套不兼容的留痕载体**、
**3 种裁决形状**。本层把它们**只读**投影成同一个 `Claim` 流，用同一个 `Registry` 管起来，
用同一套 `Check` 判、同一套 `Verdict` 记账，几何判据一律走空间/沿边索引。
**只加不改**（不碰任何既有类与既有 `no_delete.*` 键），**默认关**（`CV_UNIFIED=0`），
打开后只往旁路 `_assigned/<case>.json` 加一个 `unified` 键 —— **交付 `<case>.json` 的字节不变**。

## 2. 核心类型（`cvparts/unified.py`）

| 类型 | 字段 | 作用 |
|---|---|---|
| `Claim` | `slot, value, score, source, by, evidence, region, attrs, at` | 5 种历史表示的**公共投影**：一条「某槽位可以取某值」的候选。`kind = slot.split(":",1)[0]` |
| `Verdict` | `slot, kind, before, after, rule, by, at, detail` | 裁决。`kind ∈ hard/soft/trunc/overwrite/keep`；`as_event()`→`Event`、`as_demotion()`→`Demotion`（**直接复用 `cvparts/hypo.py` 的形状**，永不取 0） |
| `Check` | `name, run, kinds, by, at, enabled, docs` | 一条校验。**四个适配器把既有各路校验接口全包进来**（见下） |
| `SlotView` | `slot, claims, decided, decided_by, region, attrs` | 一个槽位的合并视图；`best/second/margin/ambiguous`。`add()` **同值合并**（同 `key()` 取最高分、`evidence["also_from"]` 追加来源），与 `hypo.Slot.add` 同义 |

槽位种类（`kind`）：`comp`（元件框）、`pin`（stage1 脚点/沿边列，**无值**，只作几何与沿边锚）、
`pin_number`、`pin_name`、`desig`（位号）、`partname`、`net`、`value`。

**唯一性域 `UNIQUE_KINDS = ("desig",)`**：只有位号在全局必须唯一；脚号/脚名只在**同一颗元件内**
唯一（实测 case 5 五颗 IC 各有 `pin_2`，裸 `by_value` 撞号会报 14 条、14 条全是它），
网络成员集天然重复。所以 `summary()` 同时报 `n_conflicts`（裸）与 `n_uniq_conflicts`（唯一性域），
旁路 JSON 只落后者。

### 2.1 四个适配器 —— 「泛化当前的各个交叉验证接口」的落点

| 适配器 | 包的旧形态 | 实例 |
|---|---|---|
| `Check(name, kinds, run=fn)` | 已经返回 `Verdict` 的 | 新增校验 |
| `Check.adapt(fn)` | 返回裸 dict / `(kind, reason, after)` | 表单式校验 |
| `Check.predicate(fn, fail_kind, rule)` | 只返回布尔「不合格」 | `plausible`/`priors` 的谓词式判据；**合格也留 `keep` 痕** |
| `Check.from_issues(fn, map_slot=)` | **跑一遍整池、返回可疑项清单** | `fusion/plausible.py:117 check(pool)`、`fusion/priors.py:1083 Priors.check(pool)` —— 每项 `{kind, severity, why, slots, nets, hint, need_llm}`，`severity >= 0.7` 折算 `hard`、`why` 记成理由、`slots` 里每个槽位各收一条判定，`map_slot` 负责把旧槽位命名（`comp.c1.key`）翻成统一槽位名（`desig:c1`）。**整池审计每个注册表只跑一次**（结果按槽位缓存），不是每槽位跑一遍 |

## 3. 高效中间过程的数据结构（三层索引 + 一个议程）

| 结构 | 键 | 用途 / 复杂度 |
|---|---|---|
| `GridIndex` | 框 → 网格单元（`CV_GRID_CELL`，默认 64px） | `near(box, r, kinds=, exclude=)` 只扫邻近格、按**真实框距**二次过滤后排序。用于「位号该贴哪颗元件」这类近邻判据。带 `n_query` 计数（自检断言「几何校验确实走了索引」） |
| `AlongIndex` | `(cid, edge)` → 按沿边坐标排序的数组 | `rank()` / `neighbors(slot, attrs, k)` 用 `bisect` 取沿边最近 `k` 个（按 \|Δ沿边\| 升序，平票取坐标小者）。边 = `side`，沿边 = `x`（左右边）或 `y`（上下边） |
| `Registry` | `by_slot` / `by_value` / `kinds` / `claims` / `checks` / `verdicts` | 候选总账。`add/add_many/decide/slot/slots/value_slots/conflicts/index/along_index/near/register/run/record_verdict/summary/to_json`。**`value is None` 不进 `by_value`**（空值不算撞值） |
| `Agenda` | 优先级 = 槽位候选**分差** `margin` | `from_registry()` 跳过已裁决与单候选槽位；`from_pool()` 直接吃任一历史候选池（`ClaimPool`/`CaseHypotheses`/`{slot: Slot}`/`{cid: [dict]}`）。`CV_AGENDA_MAX` 限长 |

## 4. 投影（全部只读）

`project_stage1(doc)`：`components` → `comp:<cid>`（`value=None`，region = `bbox_img`）；
`pins` → `pin:<cid>:<i>`（±1px 小框）；`pincol` → `pin:<cid>:<idx>`（attrs 带 `edge/along/pitch/x/y/synth`）；
`nets` → `net:<nid>`（value = 成员元组，score = `n_seg/10`）。

`project_assigned(assigned)`：`desig_slots[cid]` → `desig:<cid>`（`value=canon`，evidence 带
`text/conf/d/box_i/type_fix`，attrs 带 `raw_text`）；`comps[cid].designator` → 再投一条同槽
（source `stage2:designator`，score 1.0）⇒ **同一槽位的两条来源会自动合并**；
`partname` → `partname:<cid>`；`pins` 按**两层字典**遍历（`key → {number|name} → 印字`）→
`pin_number:<cid>:<key>` / `pin_name:<cid>:<key>`；`net_labels` → `net:<nid>`。

`load_case(arm_dir, case)` 直接读 `runs/stage1/<case>.stage1.json` 与 `runs/stage2/_assigned/<case>.json`。

## 5. 内置 6 条校验（默认只读留痕，不改分）

| 校验 | 判据 | 档位 |
|---|---|---|
| `desig_unique` | 同一位号被两颗以上元件占用 | `soft` |
| `desig_near_comp` | 位号框最近元件 ≠ 自己（`CV_DESIG_NEAR`，默认 60px，走 `GridIndex`） | `soft`，理由点出是谁 |
| `pin_pair` | 有脚号无脚名 ⇒ 会被 `stage2/assemble.py:1144` 的 `num_of` 过滤**整脚丢掉** | `hard` |
| `pin_column` | `idx` 与沿边坐标**反序**（走 `AlongIndex`，如 5.13「重启编号」那种元件） | `soft` |
| `region` | 候选 region 缺失/退化 | `soft` |
| `spelling` | `raw_text` 与最终值不一致 | 只标不判 |

## 6. 集成方式（opt-in 旁路）

`eda-pcb/stage2/run.py`（在既有 `no_delete` 旁路块内、`a["no_delete"] = _nd` 之前）：

```python
if os.environ.get("CV_UNIFIED", "0").strip().lower() not in ("", "0", "false", "off", "none"):
    from cvparts import unified as _uf
    _reg = _uf.Registry("case%s" % case)
    _reg.add_many(_uf.project_stage1(doc))
    _reg.add_many(_uf.project_assigned(a))
    _reg.register(*_uf.default_checks())
    _reg.run()
    _nd["unified"] = _reg.to_json()
```

`pred = build_doc(...)` 在 `run.py:263` 就定稿并已落盘，这里只动旁路 dict `a`
⇒ **交付文档字节不变**（见 §8 实测）。自带 `try`，坏了只写 `unified: {error: ...}`，不牵连 `no_delete`。

⚠️ 坑：**不能**写 `from . import assign as _as`。`stage2/__init__.py` 的 `from .assign import assign`
把包属性 `stage2.assign` 遮蔽成**函数**，实测 `AttributeError: 'function' object has no attribute 'LAST_CONFORM'`；
要取模块级列表就 `from .assign import LAST_CONFORM`。

## 8. 实测读数

自检：`自检 44 项：全部通过`（含 `GridIndex 与暴力枚举一致`、`降权分永不取 0`、
`事件数 = 判定数（含 keep）`、四种投影形状各一条、四个适配器各一条、沿边同序/反序各一条、
脚号跨元件重复不算唯一性撞号 / 位号重复算、整池审计每个注册表只跑一次 + `map_slot` 翻译）。

真图（`work/_fast_out_cvu1` case 5）：

```
候选 219 条 / 槽位 206 个 / 取值 79 个
  {'comp': 26, 'desig': 11, 'net': 44, 'partname': 6, 'pin': 76, 'pin_name': 21, 'pin_number': 22}
校验 6 条 → 判定 98 条（其中降权 7）  撞号 14（唯一性域 0）  需复核 0  空间查询 11
撞号：唯一性域 0 条（其余 14 条都是脚号/脚名跨元件重复，正常）
降权（前 5 条，rule = 有脚号但没有脚名 ⇒ 会被 num_of 过滤整脚丢掉）：
  hard  pin_number:c0000:3  1.000
  hard  pin_number:c0001:1  0.999
  hard  pin_number:c0001:7  1.000
  hard  pin_number:c0017:0  0.619
```

—— 即**统一层第一次跑真图就把 ②a 的失分路径指了出来**：这 7 根脚有号无名，
按 `stage2/assemble.py:1144` 的 `num_of` 闸门会被整脚丢掉。建模过程中修掉三处假信号：
stage1 脚点曾被建成 `pin_number`（76 个槽位并成一个 `null` 撞号）、`comp` 槽的 `value`
曾取元件类型（造出 19 条假撞号 "box"/"c"/"gnd"），前者改为独立 `pin` 种类、后者改 `None`；
裸露的 `by_value` 撞号曾把「5 颗 IC 各有 `pin_2`」报成 14 条撞号 ⇒ 拆出 **`UNIQUE_KINDS`**
（只有**位号**是全局唯一域；脚号/脚名只在同一颗元件内唯一，网络成员集天然重复）。

端到端逐位不变（`CV_UNIFIED=0` : `cvu0` / `=1` : `cvu1`、`cvu1b`，`tools\eval\fast.py --cases 5 --no-vlm`）：

9242 B 逐位相同**；`CV_UNIFIED=1` 时旁路 `_assigned/5.json` 多出 `no_delete.unified`
