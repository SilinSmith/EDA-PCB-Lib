### 交叉校验清单的三条结论
1. **只有一处真硬删**：`stage1/bigic.py:117 _border_wire_frac`（判为导线环路 ⇒ 整块矩形消失）。其余「丢弃」旁**全部**留痕。
2. **留痕形状有 6 套不兼容的载体**：`LEDGER.demote/record`、`LAST_CONFORM/LAST_CONFORM_EXTRA`、`LAST_DEMOTED/LAST_RESERVE`、`designator_dropped`、`own.thin` 的 `ledger` 参数、`plausible/priors` 的 `sus` 清单。
3. **互证的两个方向都在用**：正向（读出的前缀 ⇒ 判类型，`CONFORM_KEY`）与反向（类型 ⇒ 允许的前缀，`TYPE_PREFIX`/`key_fits_type`）。

## ③ 统一 `Claim`/`Check`/`Registry`/`Agenda`/`Verdict`/`Ledger` 最小 API

### 3.1 设计原则（全部来自本仓既有事实，不是外部范式）
* **P1 只加不改**：新层只**追加** `Alt`，绝不改已有 `alts`/`desig_all` 的内容与顺序。
* **P2 判负必须留痕**：任何 `Verdict` 都写 `Ledger`，分数取四档之一，**永不取 0**。
* **P3 逐位不变优先于统一**：新层默认全关；开启时必须证明**候选集与排序都不变**才允许改行为。
* **P4 不引第三方**：只用 `dataclasses` + 现有 `cvparts/hypo.py`。

### 3.2 最小 API（可直接放进 `cvparts/hypo.py`，新增 ~120 行，**不改现有类**）

```python
@dataclass
class Claim:
    slot_id: str                    # 统一槽位 id：comp.<cid>.<field> / pin.<cid>.<k>.<field> / net.<key>
    value: Any                      # 候选值（字符串/数字/None）
    score: float = 0.0
    source: str = ""                # 命名空间化：ocr:* / vlm:* / cv:* / prior:* / solve:* / fix:*
    evidence: dict = field(default_factory=dict)
    at: str = ""                    # 产生阶段，如 "stage2:assign"
    # 桥接：把现有 5 种表示投影成 Claim，不要求它们改写

@dataclass
class Verdict:
    slot_id: str
    kind: str                       # keep|demote|drop|merge|split|overwrite|truncate|abstain
    before: list = field(default_factory=list)
    after: Any = None
    rule: str = ""                  # 校验器名，如 "key_type_mismatch"
    by: str = ""                    # 谁下的裁决
    at: str = ""
    lost: float = 0.0

class Check:                        # 单条交叉校验的可组合形式
    name: str
    def subject(self, reg) -> list: ...      # 我要审哪些 slot
    def run(self, reg, subj) -> list[Verdict]: ...
    enabled: bool = True

class Registry:                     # 槽位 ⇄ 候选 ⇄ 证据 ⇄ 取景框 的唯一索引
    def __init__(self, pool): self.pool = pool
    def claims(self, slot_id) -> list[Claim]
    def add(self, c: Claim, keep: bool = True) -> None      # 透传 ClaimPool.add
    def region(self, slot_id)
    def slots(self, pred=None) -> list[str]

class Agenda:                       # 「该去问谁」= 现有 unresolved/sus/rescan 的统一视图
    def push(self, slot_id, why: str, need_llm: bool, severity: float) -> None
    def pop(self, n: int) -> list[dict]        # 按 severity 降序
    def from_pool(self, pool, sus=None) -> "Agenda"

class Ledger:                       # 复用现有 cvparts/hypo.Ledger（已具备 demote/record/touched_slots/dump）
    ...                             # 只新增 Verdict → 现有 Event 的适配器，不新建类
```

### 3.3 逐位不变的默认保证（硬性验收）
1. **所有 `Check.enabled` 默认由 env 控制且默认 `False`**（沿用 `env_on(name,"0")` 惯例），唯一例外是已被证明「只写旁路报告」的 `CONFORM_AUDIT`。
2. `Registry.add` 走 `ClaimPool.add` ⇒ 复用 `Slot.add` 的**同值合流 + 重排**语义（`hypo.py:241-260`），不引入第二套排序。
3. `Agenda` 只**读** `pool.unresolved()`（`:345`）与 `plausible.check()`，不改变它们的返回顺序。
4. **验收脚本**：对 10 张官方图各跑一次，断言 `_assigned/<case>.json` 的 `comps/net_labels/desig_slots` 与交付 `<case>.json` 的 `components/pins/nets` **逐字节相同**（`fusion/doc.py:305 diff(a,b)` 可直接用）。

### 3.4 高效中间数据结构
* 一致性要求：`slot_id` 必须是**唯一主键**，并且 `desig_all`/`desig_slots` 视为同一对象（`assign.py:1232`）——统一层**绝不复制**这两份。
* 索引：`Registry` 内部只用 `dict[str, list[Claim]]` + `pool.regions` 现成 dict，不新建嵌套结构。
* 只存指针：`Claim.evidence` 保留原 dict 引用而非拷贝，避免 `desig_all` 双份内存（10GT 量级下 `n_slots` 数百，开销可忽略；220 张需注意 `MAX_ALTS=6` 与 `LEDGER_DETAIL_LIMIT=600` 已是现成上限）。
* `Agenda` 用一次 `heapq` 或排序列表；`severity` 来自 `plausible.SEV_*`。

### 3.5 迁移路径（四步，每步都可独立回滚）
1. **只读影子层**（零风险）：新增 `cvparts/claims_bridge.py`，把 5 种表示**投影**成 `Claim`，不写任何东西；用 `diff()` 验证投影覆盖率（实测 `claims.vlm_keymap` 已证明直接对 cid 会静默全错 ⇒ 投影必须走 `vlm_keymap`）。
2. **Verdict 归口**：让现有 6 套留痕载体**额外**产出一条 `Verdict`（`ledger` 参数已是现成接入点：`own.thin(...,ledger=)`、`structmatch.rebind(...,demote=)`、`assign` 的 `LAST_CONFORM`）。此时 `no_delete.*` 键**一字不改**。
3. **Check 抽取**：把 `plausible.check` 的 ①-④ 与 `priors.check` 的 5 类**包装**成 `Check` 子类，`run()` 内部调用原函数，输出转 `Verdict`。原函数保留。
4. **Agenda 统一调度**：`FUSION_RESCAN` / `AUDIT` / `CROPFIX` / `JUDGE` / `ITERATE` 五个消费者改从 `Agenda` 取任务，`plan()` 语义不变。

### 3.6 风险与反模式（明确禁止）
* ❌ **不要**为了统一而改 `_assigned/<case>.json` 的 `no_delete.*` 键名或嵌套：`stage2/run.py:294-307` 与 `tools/diag/_pinledger.py`、`_netwhy.py` 都会静默失联。
* ❌ **不要**把 `desig_all` 与 `desig_slots` 拆成两份（`assign.py:1232` 是同一个对象，拆开会产生两份真相）。
* ❌ **不要**让 `Claim.score` 与 `Alt.score` 存在两套归一化尺度：`alt.score` 里混着 fit/conf/距离衰减/证据加成（`assign.py:734 _score`），统一层只做**透传**，不做二次缩放。
* ❌ **不要**把 `drop` 变成 `score=0`：`structmatch` 自检 `:546-552` 已把这条钉死。
* ❌ **不要**在 stage1 里用全局 `LEDGER` 期待跨进程聚合：`stage1/pipeline.py:53` 走 `ProcessPoolExecutor`，每 worker 一本账，只能靠产物带回。
* ⚠️ `stage2/__init__.py` 有 `from .assign import assign`，包属性 `stage2.assign` 已被**函数**遮蔽 —— 取模块级列表必须 `from .assign import LAST_CONFORM`（`stage2/run.py:288-291` 的实测教训）。
