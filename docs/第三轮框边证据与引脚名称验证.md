# 第三轮：框边接入证据与引脚名称匹配

## 最终改动

型号文字笔画会产生框外假引脚，旧名称匹配只比较距离，可能让它抢走框内 EN。
本轮在最终合并的 IC 候选上添加实际长框线、沿法线墨迹连续性和外侧文字墨迹证据；可信引脚先匹配名称，待定候选只用剩余名称，明确字形候选不匹配名称。

名称使用文字bbox沿边投影和相对框边的间隙，避免右侧缺脚时把LX强配给左侧IN；长名称跨中线和角落名称仍可保留。OCR框不会擦除图像，误宽OCR框包住单根短脚时保留待定；硬拒绝文字假点还需实际多组字形墨迹。

证据仅影响引脚名称。号码使用原点、原边和既有完整整排匹配；本轮没有改重复号码代表选择。候选点、元件框和第一阶段网络原样保留；提交JSON不添加诊断字段。`STAGE2_PIN_TRUST_BIND=0`可以关闭名称机制；旧缓存无证据、长度失配或全部对应失效时退回旧路径。

## 局限与后续

- 本轮没有解决黑白连续线的tip坐标，原固定偏移仍存在。框边base用于名称归属，不能替代提交point应记录的tip。后续方案见[黑白引脚坐标](黑白引脚坐标后续方案.md)。
- 几何可信度不是校准的正确概率；真实短脚与外侧文字实际重叠时仍可能难以区分。边框未确认或证据不足时保留待定，也会留下部分假点。
- 名称OCR漏读、漏检整颗元件、图像中未印出的GT身份及公开标注误差仍影响得分。没有根据GT名字在生产逻辑中做逐图特判。
- 号码流程与已有重复OCR/无名先占号政策未改；名称占字变化仍可能间接改变号码候选池。没有重新验证启用VLM、模型仲裁或融合后的完整运行。
- 本轮数字、坐标和四项评分的逐图变化见[完整实测JSON](reports/第三轮框边证据完整推理实测.json)，下降样例也完整保留。
