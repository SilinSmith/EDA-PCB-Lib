### 2.9 相邻信息度量：位号的「邻座」到底有多少信号（2026-10-09）

动机：User ref m40034 第三项问「高维空间里分布元器件」的构想能不能用来衡量**相邻信息**。
`fusion/axis.py` 的 `build_axes()` 只做了最窄的一种对齐（同前缀 + 同一 y 带 + 水平），
`reports\工程哲学.md` 自认「只做了最窄的一种」。**先量信号，再决定要不要泛化。**

尺子：`tools\diag\adjmeas.py`（`--poolscan` 两种口径）；料 = `work\_s2_220mix\_assigned` + `work\_cases_w28.txt`
（官方 9 + 派生 19，共 **639 个 GT 位号**；GT 框是镜像帧，翻成 PNG 帧 `y = H - y_gt` 后与候选框同帧）。

**(a) 生成式相邻信息 ≈ 0**：GT 位号按同前缀排序、副轴带 8px（放宽到 30px 结果不变）、
主轴间距 ∈ [0.25,4]×中位框宽、成员 ≥3、号严格单调 —— 满足的 run 只覆盖 16/639（**2.5%**），
其中「池子里读不出、但**邻座的真值号**插值能推对」只有 **2 个（0.3%）**。
⇒ 原理图里**几何相邻 ≠ 号相邻**（位号是设计者随手分配的标识），
「用邻座推号」这条路没有可兑现空间；`axis.py` 已经吃掉了唯一有的那一口（位置单调）。

**(b) 真正的相邻现象是「偷邻居的号」**：把每个 GT 位号映射到元件自己的候选清单
`desig_slots` 后分桶（`--poolscan`，639 个）：

| 桶 | 数量 | 占比 | 含义 |
|---|---|---|---|
| `chosen_ok` | 254 | 39.7% | 选中的就是它 |
| `near_not_chosen` | **78** | **12.2%** | ★ 正确读法就在**这颗元件自己的候选清单**里、且 ≤60px，却被**邻座的号**顶掉 |
| `far_not_chosen` | 4 | 0.6% | 正确读法在 >60px（距离分布 60~80:1 / 80~100:2 / 150~250:1） |
| `not_in_pool` | 239 | 37.4% | 池子里根本没有（读/检测问题） |
| `no_slot_unknown` | 64 | 10.0% | 250px 内连候选框都没有 |

典型 `near_not_chosen` 全是**相邻换位**：`1 C151→C152 @54.6px`、`1 C153→C1S4 @53.6px`、
`1 C159→C160 @56.1px`、`2 R1→R2 @22.8px`、`4 C1→C2 @28.8px`、`7 C1→C2 / C2→C3 / C5→C6`、
`10 C4→C5 / C7→C8`、`0011 C8→C10 / C10→C1 / C5→C6`、`0027 C6→∅ / C7→C2`。

⇒ 结论：相邻信息的价值不在「推」而在「**归属**」—— 应把它当**一对一约束**
（一段邻域内「元件 ↔ 位号」应是双射且总距离最小），而不是当生成先验。
这一步的候选修法（**同前缀邻域内最近文本一对一重分配**）尚未实装，属于
`fusion` 层（`axis.py` 之后）的下一刀，收益上限 = 上面那 78 个位号（其中官方 9 张里 20+ 个）。

**(c) 顺带量到的另一块**：`not_in_pool` 239（37.4%）+ `no_slot_unknown` 64（10.0%）
= **47%** 的 GT 位号在读/检测这一环就没有正确读法 —— 这与 §2.3 的位号天花板一致，
也是为什么位号通道的杠杆在**读**（CRNN/框），不在**排序**。

   671 行官方裁剪行 —— `ocr_mix` `tight 0.6349 / pad 0.7884`；`ocr_pipe_v1` `tight 0.8480 / pad 0.8584`。
   注意这不是管线里的 `tight_ink_box` 路径（那条已在 `stage2\text.py:114-121` 端到端量过：切
   `pin_number,pin_name` 采纳、切全 5 角色 **不许**）。
3. **按置信度择优**（同一框两口径/两权重取 conf 高者）：`ocr_mix 0.5723`、`ocr_pipe_v1 0.8167`、
   四格合取 **0.5559** —— **都低于任一单口径** ⇒ 置信度**跨口径/跨权重不可比**，这条路是死路。
4. **按角色语法挑口径**（designator `^[A-Za-z]{1,4}\d{1,4}[A-Za-z]?$`、pin_number `^[A-Za-z]{0,2}\d{1,3}[A-Za-z]?$`、
   pin_name/value 字母数字式）：三种规则全部 **= 0.7884**，一分不涨（没有一行「pad 不合法而 tight 合法」）。
   顺带记下：**pin_number 的 GT 可能带字母**（`_padchk_pipe.jsonl` 里 `0177 gt=A1`，读成 `1A1`/`141`）。

⇒ 引脚通道剩下的两个真杠杆：**归属修法要配「读可信度」闸门**；**读侧要换语料重训**
（微调权重在官方同源字体上更好 0.858 vs 0.788，却在我们自己的框分布上更差）。

## 6. 归因尺子（怎么把失分拆成可行动项）

| 尺子 | 脚本 | 它回答什么 |
|---|---|---|
| netH 三层分解 | `tools/diag/_netloss.py` | GT 网成员 → ① 缺键 ②a 有名元件缺脚号 ②b `∅` 缺脚号 ③ 拓扑错 ④ 正确 |

| 引脚号 | `tools/diag/_numread.py` | 按**框宽分桶**的读数准确率 + 归属错/识别错归因 + `--dump` 错例拼图 |

| GT 保真度 | `tools/debug/ledger.py`、`tools/debug/report.py` | 把官方打分过程**逐条摊开**；自造 GT 会骗你 |
| 框外文字带 | `tools/diag/_pinband.py` | 某颗 IC 框外的小文字框，按离框边多远分列 |
| 宽框裁片 | `tools/diag/_widebox.py` | 把「框宽 ≥ N」的裁片连同邻域渲染出来，人眼判「框里到底几个字形」 |
| **阶段耗时黑洞** | `tools/diag/_prof1.py <case>` | 单张 stage1 的 cProfile，直接落到「是哪一行在等网络」 |
| **一次全量跑的分段统计** | `tools/diag/_stage220.py --run <产物目录>` | 阶段一 stats+timing、阶段二位号/引脚号/引脚名读出率、按官方权重打分与最差 N 张 |
| **引脚四段漏斗** | `tools/diag/_pin200.py --n 60` | 键没配上 / 键配上没这根 / 名字不同 / 坐标超差；`--emit` 看产出率 |
| **上帝键上界** | `tools/diag/_keyoracle.py --n 60` | 位号全修对能涨多少（并暴露「强行配对」的作弊分） |
| **绑定的影响被消掉后的引脚** | `tools/diag/_pinoracle.py --n 60` | 同一元件键下取离 GT 点最近的预测引脚，看还剩什么缺口 |

| **引脚名该不该允许框外** | `tools/diag/_gtpinplace.py`、`_pinlabel.py --n 60` | GT 引脚点离框多远、那附近有没有我们的文字、文字在框内还是框外 |
| **VLM 延迟与触发面** | `tools/diag/_huetime.py --count` | 有多少张会发这一次询问、整图 vs 缩图的延迟差 |
| **「读错」还是「没产出」** | `tools/diag/_ocrstat.py --split 10GT` | **按位置**绑定槽位（先几何再看字符串），给出号的/名的「完全对/整串读错/空/截断/多读」计数 + 截断样本的**文字框像素宽度**（证明是 CRNN 少读还是检测框太小）。按号查会把读错的混进「没槽位」（对比 `_pinnamepair.py`：按号只能查到 94/136） |
| **读法全对值多少（上界）** | `tools/diag/_ocroracle.py --out <产物> --cases …` | 上帝视角改写 `pinname` / 引脚键（并同步 `hyperGraph`）后重新打分 ⇒ **OCR 的天花板**。官方 9 张 **58.63 → 63.23（+4.60）**。**任何「要不要重训/换模型」的决定之前先跑它** |
| **缺号成因分类** | `tools/diag/_pinledger.py --run --split` | 把 `pin.missing` 拆成「读对了号却没 emit」（策略）/「号读错」（OCR）/「附近没槽位」（检测） |
| **闸门/装配开关的离线单变量 A/B** | `tools/diag/_gateab.py --run <产物> [--all]` + `tools/eval/stage2_eval.py work\_gate_ab\{on,off}` | 用**已落盘**的 `runs/stage1` + `runs/stage2/_assigned` 重跑 `assemble.build_doc`（改模块全局切开关）⇒ **纯 CPU、不占 GPU、不用重跑 OCR**。`STAGE2_BOX_PIN_NEED_NAME` 就是用它量的（官方 9 −0.15 / 220 +0.10） |
| **官方档 vs 派生档的引脚键形状** | `tools/diag/_gtpin10.py --show 4` | 官方 10GT 键是纯数字（可赢）；派生档是内部计数器 |
| **单 case 的槽位实录** | `tools/diag/_pinslot.py <case>` | 一个元件名下每个引脚槽位的 `number/name` 文字与框，用来对「我们读到什么」与「图上印着什么」 |
| **引脚邻域肉眼核对** | `tools/diag/_pincropgt.py` | 把 GT 引脚邻域裁成带十字+标签的拼图：确认「十字在引脚线上、号在框外上方、名在框内」以及**我们存的文字框对不对** |
