# 第四轮：芯片框内文字资格与方向名称匹配

## 结论

已修复“跨芯片边界的编号/标记混合文字框中心落在框内，从而被当作引脚名称”的问题。先检查文字框与实际芯片本体边界，再沿引脚朝内方向分配名称。

当前指定 10GT 中，坐标误差不超过 5 像素的固定对应引脚，正确名称 **66→69**；同侧沿边诊断 **81→84**。相对正式基线恢复 3 个正确名称，原本正确的名称退化 0 个。前轮失败方向实验的 5 处退化名称也全部恢复。

完整本地平均分 **54.8198→54.8662（+0.0464）**，增幅很小；最终正确引脚 TP 仍为 46，不应把名称分配改善说成完整引脚解析已解决。

公开 200 张有已知标注错误，只作训练与大致参考，本轮未把它们用于可靠准确率统计。

两组使用相同几何、元件类型、OCR 读数和配置，实际重跑名称/号码分配和 JSON 装配；第一阶段几何及 OCR 权重未变。基线使用保存并核对过哈希的提交 `8bacedaf6b339118d2f47a79bc61ff2a426d6cf4` 中的三个原始源码文件，重新运行结果与此前逐张保存输出完全一致。本轮是固定几何/OCR回放，未重新跑完整端到端模型，也不是赛方线上评分。

名称先按几何固定对应，不用名字、位号或预测引脚编号决定对应关系；名称比较区分大小写、使用精确字符串。GT 共 136 个 `box` 引脚。

| 名称口径 | 可固定对应 / GT总数 | 基线正确 | 修复正确 | 恢复 / 原正确退化 |
|---|---:|---:|---:|---:|
| 欧氏距离 ≤5px | 102 / 136 | 66 | 69 | 3 / 0 |
| 同侧、沿边偏差 ≤5px | 126 / 136 | 81 | 84 | 3 / 0 |

第二种忽略垂直于框边方向的坐标偏差，只诊断名称归属，不代表坐标合格或官方得分。

## 实现

1. 从有效引脚证据汇总图像已确认的芯片边界。同侧锚点须一致；缺失、矛盾或异常边保持中性。校验锚点法向与切向范围，避免旧坐标影响名称评分；资格与评分共用清洗后的证据。
2. 检查整个 OCR 文字矩形是否跨已确认边，而不只看中心。允许 `max(1, min(3, 0.15×短边))` 像素的外扩；不按文字含数字与否过滤，所以 `A0`、`IO1` 或纯数字名称仍可保留。没有真实边界证据时不拿检测 bbox 作硬裁剪。
3. 合格候选按引脚朝框内的方向搜索，要求横向/纵向投影对齐。按文字近边比较距离，允许小距离差再结合 OCR 评分；搜索深度限制为半框深度和四倍文字短边的较小值，加既有对齐容差。可信点先，待定点使用剩余文字；两轮均有方向约束，名称不做数字阶梯重排。
4. 旧缓存、失效证据或缺少文字矩形保留旧路径；可信/待定两轮校准不足时分别回退原排名。号码路径保留原坐标及原规则，逐原始候选对照未发现任何号码变化。
5. 仅当新筛选确实让某个原有名称变为空，记录内部拒绝标记。要求名称输出时，同编号完整读数可替换这个新变为空的赢家；普通历史空名称策略保持原行为。只选择原接点索引，不借号、不复制名称、不把输者的网络并到胜者。该标记只在内部中间数据中，未进入赛题输出 JSON。

| 图片 | GT引脚 | GT名称 | 基线分配 | 本轮分配 |
|---|---|---|---|---|

漏引脚、黑白图的输出端点坐标、引脚号码和 OCR 字符错误仍需后续处理。OCR 把编号与笔画合并时，本轮可拒绝错误矩形，却不能自动恢复未读出的正确字符。方向最近策略也可能遇到多个邻近文字争用的歧义。

该 10GT 已用于开发，不是独立隐藏测试；这些结果不能保证其他图上没有误伤。阈值来自既有图像尺度和 OCR 尺寸约束，没有按图号、GT 名称或指定位置特判。
