## 当前评分规则

PDF准确度公式仍保留为基础：

`Score_Accuracy = 100 × (0.30 ComponentF1 + 0.25 PinF1 + 0.35 NetHypergraphF1 + 0.10 NetLineF1)`。

全部案例的准确度按全部案例数M计算；未完成案例不得分，不能只按完成数m平均。PDF规定准确度/Token组合为 `FinalScore_Accuracy = 0.95 × Score_Accuracy + 0.05 × (m/M) × Score_Token`，准确度与Token合计100分，另有数据贡献附加分10分。本次两份Q&A没有提供可替代这些系数的新公式。

| 评分项目 | 已确认的现行口径 | 仍未明确的细节 |
|---|---|---|
| 空间阈值 | 元件bbox、IC引脚、导线端点共用20px阈值，替代旧5px规定；普通元件pin位置不参与评分 | 各空间对象的具体距离计算与配对方法仍需配套正式scorer核实；不能把20px等同于某个IoU阈值 |
| 元件身份与框 | 普通元件按位号匹配，检查类型和必要文字；电源/地采用特殊匹配；bbox阈值回答明确为20px，不采用旧平台截图中的5px | 完整导出版平台 A64又答“元件是用miou去算的”；mIoU在匹配/得分中的作用、阈值及与20px的关系尚无完整定义 |
| 普通元件（非box）引脚 | `pinname`、`pinnumber`不参与评分；pin不再计位置分，也不再按pin计连接关系分，连接改按元件整体对齐 | 不能据此宣布整只元件免评；元件类型、位号、bbox及真实网络归属仍须正确。引脚数量在新版PinF1中的具体处理未单独说明 |
| box引脚（含IC） | 按图片可见编号、名称与实际连接点处理；IC引脚位置阈值为20px，连接关系仍按pin对齐；非box名称/编号豁免不适用于IC | 新版完整scorer尚未取得；连接器归入box后的全部字段细则仍以配套评分程序为准，不能直接套用普通元件免评规则 |
| 网络成员 | 普通元件按元件整体对齐，IC仍按pin对齐；R/L/C等非box引脚1/2不作身份区别，GND/电源同理 | 同元件可出现在不同net中；忽略1/2身份不等于把两端电气短接。具体集合归一化由正式scorer核实 |
| GND/电源 | 不按自动编号key对齐；按类别、值和几何位置匹配。同图同名GND/电源在算分时合并到相应逻辑net | 值缺失的容错、值的文本归一化、几何配对使用的具体对象、跨字段映射及合并后线段处理尚未取得完整算法 |
| 导线 | 端点做匈牙利匹配；端点距离阈值更新为20px；GT分段错误会更新 | 正式更新后的GT与scorer未在本次附件中提供 |
| Token | 输入Token与输出Token相加，权重相同；少消耗得分更高 | 具体统计接口、失败调用记账、平台额度以正式说明为准 |

证据：完整导出版平台 A21、A22、A27、A35、A36、A38、A42、A53、A64；汇总版评测2–7、9–11；用户本轮完整提供的四项官方测评算法更新①–④。名称/编号免评依据A21原文“非box的pinnamepinnumber不参与评分”，其适用范围是非box，不能扩大到IC。

电源合并的回答必须结合提问中的“同名”理解：不能把GND、3V3、5V等不同逻辑电源全部短接成一个net。此处是对答复适用范围的解释，最终名称/值匹配仍需正式程序。

LED在本地 `type_list` 中属于非box，因此其引脚名称/编号按上述字段豁免。本次两份Q&A没有给出“整类LED的位号、类型、bbox都不评分”的规定；如用户另有官方条款，应补入来源。用户指定的额外统计过滤可以另列，但不能当作官方免评规则。

## 当前用户协作约束

以下是本聊天已确认的执行要求与定位规则，和官方评分口径分开记录：

1. 引脚优化与当前正确率统计不追求官方JSON引脚坐标；有依据的彩图测量优先，现有GT坐标错误不能迫使实测点移位。
2. 有真实红绿交界时优先取交界；其他配色也按引脚与导线相接的定义找交界，包括已确认的黑红交界。排除本体内部换色。
3. 引脚先直接抵达结点、此前没有导线交界时，取该直接结点中心；有绿线后才抵达远端结点时，不越过已有交界。
4. 允许极短绿色导线。单轴向一像素连接段双方共用其中心；多行/多像素混色段，两端分别取各自红引脚与色段的交界。
5. 对称电容/电阻等可用可靠对侧实测长度推算另一端；确认为两直引脚红红相接的拐点可作接点。不能把所有导线弯折当引脚接点。
6. 同图、同形、同尺寸符号可复用有可靠实测依据的引脚长度；难分的细弱混色段也可用该备用方法。必须标注参照与推算依据。
7. 对侧与所有同图参照都不可靠、或多个可靠参照冲突且没有其他唯一依据时，反馈规则条件缺失，不能猜训练答案或凭多数选点。
8. 黑白非IC精确坐标优化继续暂缓；最新官方又明确最终不设黑白评分案例，后续比赛优化优先彩图。已有黑白兼容代码与回归可保留。
9. 当前统一引脚源码已整合IC v53与非IC R21，位于本聊天的独立工作树。另一聊天的原工作树继续保留，不整文件覆盖其未完成改动。

## 对当前代码与结果的影响

- 彩图端点、结点、短色段及可靠长度定位规则继续有效。非box名称、编号、pin位置免评，且网络按元件整体对齐；真实端点仍用于判断导线归属和连接关系，不能因此忽略漏接、误接或把元件两端短接。
- 本轮已补全四项评分更新；文档中的20px是官方评分容差，不是要求将识别代码中所有5px检测或吸附参数一律改成20px。识别内部参数与评分阈值须分别评估。
- 优先检查彩图GND/电源文字、成员保留和逻辑net归一化，以及连接器走box路径的正确性。旧的“随机编号必然FP所以过滤”的理由不能当作新评分口径。
- 本地 `schematic_parser/metrics.py` 的 `latest` 默认已统一bbox/IC引脚/导线端点20px、普通元件整体与IC逐pin的两级网络比较、电源/地类别/值/几何匹配；普通元件引脚名称、编号、位置不进入PinF1。电源几何暂沿用可配置的bbox判据，IoU≥0.5仍只是本地可选设置；不能宣称与尚未取得的新版官方scorer逐位一致。
- 快速评分、阶段二评分、清单比较和逐项错误报告默认使用 `latest`。`protocol2`、`protocol` 以及独立的旧判题机复刻保留用于历史对照；不同规则的分数变化不能写成识别提升。
- 装配层已补充电源/地 `value` 输出：可靠的归属OCR保留文字原样；标准GND符号按含义输出GND；电压不默认猜测，冲突或无可靠文字时保留未知。此改动不移动引脚、不合并网络。
- 已提交PR中的948项测试、IC47图重放及非IC10GT回归，是整合未回退的证据。既有229/233、233/233、88.73%等结果保留原数据和指标定义，不标成新版官方总分，也不因规则更新而改写旧测量。
- 第一张旧10GT灰度图的8个电源/地引用遗漏仍是兼容性问题；最终不设黑白图后，不能直接用它推断正式彩色案例会漏同样数量。
- 最新GT、元件库、type_list和正式评分程序需要按实际文件版本与哈希核对；“会更新”“这周/下周更新”是发布承诺，不能冒称已经取得新版。
