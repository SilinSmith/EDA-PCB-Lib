## 0 两把尺子（先记住这个，否则后面所有数字都会读错）

| 尺子 | 命令 | 含义 |
|---|---|---|
| **官方交付口径** | `python -X utf8 -m schematic_parser.evaluate --pred submission\final_results --split 10GT` | 交付产物；`submission/run.py` 会按 VLM 预探**自动打开** `STAGE2_PINROT` 等开关 |

计分公式（`tools/diag/_ro220score.py:31`，两套基线各验到 5 位）：
`score = 0.30*component + 0.25*pin + 0.35*netH + 0.10*line`
⇒ 每 +0.01 分别值 **+0.35 / +0.25 / +0.10** 分（netH 最贵、netL 最便宜）。

## 2 四条通道为什么收口

### 2.1 component（交付 1.0000，满额）
公开 10 张上已满分，没有可加的量。

### 2.2 pin（交付 0.8166）
* **读得到的都读到了**：官方 10 张 21 个 box 元件、GT 136 脚、我方 131 ⇒ 召回 **96.3%**（确定性 91.9%），0 个"一脚未发"的元件（§5.129）。
* **错项集中在锚点**：锚点偏差占 pin 错项 **82.0%**（确定性 71.6%）；`O_anchor` 神谕 = +0.1388 pin f1 = **+3.47 分**，但那是"已知 GT 真值平移量"（§5.129）。
* **锚点偏移是「每元件每边」恒定**：41 个 (元件,边) 组里 28 个（68.3%）偏移恒定，按恒定值修正值 **+1.74 分**；但**色转折探针无法 GT-blind 估计**（命中 1/21，施行 **−9.32 分**）（§5.131）。
* 旋转、库补号、闸门三路都已试停（§5.132 / §5.133）：`STAGE2_PINROT` 已覆盖旋转（残差 +0.36 分）；`libpins` 用库补号会踩"库号↔名 ≠ GT 编号"（`TPS2553DBVR` 库 `/FAULT`=4 而 case6 GT 写 3，一处 −0.16）。
* ⇒ **唯一会重开这条线的是 GT 侧锚点口径变更**（新 GT 若把引脚锚点定义成"红绿导线交点"）。届时要做的第一件事：重跑 `tools/diag/_pinanchor.py`，看"每元件每边恒定"是否还成立。

### 2.3 netH（交付 0.8254）
* 网络级配对失败**结构性不存在**（`c5_nonargmax_pairs = 0.0`）；`soft_tp = Σ Dice`、`f1 = 2·soft_tp/(N_pred+N_gt)`（`schematic_parser/metrics.py:561-567`）。
* 分解：池外成员 23.6%（其中"压根没检出" 11.4）、该并没并 0.0、该分没分 0.1、凭空网 0.3。
* 神谕：`O_full +0.1746`（6.11 分）、`O_member +0.1599`、**`O_full_W +0.0157`（0.55 分）**、`O_full_U +0.0125`（0.44）、`O_merge_same +0.0000`（同名并网无收益）、`O_drop_junk +0.0072`（§5.128）。
* ⇒ 可 GT-blind 兑现的量 **< 0.7 分**（自设止损线）⇒ 止损。

### 2.4 netL（交付 0.5780）
* 失败形态是"同一片几何切在不同位置"：639 GT 段 / 720 我方段，tp 382~384、fn 255~257、**fp≈fn**；case3/4/6 段数逐位相等（47/60/86）却只配 28/35/49（§5.126 的 `_nlaccount.py`）。
* 单算子归因（确定性口径，逐位）：`STAGE2_EDGE_EXT`（`nlext0`）**−0.0927**、`STAGE2_EDGE_TRIM` −0.0211、`STAGE2_EDGE_CORNER` −0.0104、`STAGE1_SPLIT_JUNC_NODES` +0.0005 ⇒ 误差 75% 由"边端点外扩"决定，且**死在 stage1/pskel，不在 stage2**（`STAGE2_TRACE_DUMP` 追踪：坏端在 stage2 只被搬动中位 2.00px）。
* 换切点不可行：九类锚点联合上界 **405/639 = 0.634 < 我方现有端点自身 412/639 = 0.645**（§5.127）⇒ 零增量。
* ⇒ 止损，不动切点/端点算子。已回滚的实验只在 `stage2/assemble.py:1033-1039` 留了 8 行 docstring 神谕纪录。

## 3 200 池的结构事实（"池上分低"不等于"我们没做好"）

1. **引脚标注稀疏**：池上 GT box 引脚 **9119** 个，而整份 GT 文字清单里 `pin_number` 只有 **259 行**；`pin_f1 = 0.0989` 的一大半来自这里（§5.148）。
2. **键有 19.3% 是标注伪影**：`pin_0.1uF`、`pin_3V3` 这类用网名/值当键（1757/9119）；另外 GT 元件的"身份"要用 `components` 的 **dict key**，`Name` 字段是型号（例：`0031-Datasheet` 21/21 键可用但只有 19/21 `Name == key`）。
3. **∅（未命名）通道是符号通道**：4033 个 ∅ 键元件（43.98%）的 `canon_type` 没有一个是 box（`gnd`/`v`/`net_*`…），落其上的 4299 个 GT 脚里 box 类型 **0** ⇒ 被 `pin_f1(pin_box_only)` 结构性排除；且它们**已被坐标通道配上 3919 = 97.2%**（keymap 6725）；"成员全 ∅"的 GT 网 468~469 个与我方网成员集合原始匹配 **0**（§5.148）。
4. **两池的引脚锚点约定相同**（GT 引脚 100% 在 bbox 内，`d_bbox` 中位都是 10.0）⇒ 200 池**不是**新口径的预演（§5.137 M3）。
5. 池上的空产物地板 = **0.6250**（5/200 张因 GT 无 IC 白送 25 分；其余 195 张 26.9648）。

## 7 会吃掉结果的坑（每条都真的踩过）

1. **坐标翻转**：GT 是左下原点，读图必须 `y_img = H − y_gt`（两池都验证过：同人口下脚号可读 662 vs 19）。
2. **`gap` 用显式 `None` 判断**：`gap = 0.0` 会被 `or` 吃掉（`r.get("gap") or 1e9` 是 bug）。
3. **图路径要走 `schematic_parser.data.discover(DATA, ('200_train_cases',))` 的 `c.png_path`**：拼 `DATA/200_train_cases/<stem>.png` 会让 **195/200 张找不到图**，而且症状是"ink 恒 False"这种**假零**。
4. **`case_id` 是数字干**（`'0001'`），池的行键是 `'0001-KiCad'` —— 映射要用前缀。
5. **UTF-16 日志**：`work/_gen220/m11c.console.log` 这类要 `decode('utf-16')` 才能读。
6. **不要用 PowerShell 文本管道改仓库 UTF-8 源文件**（`Get-Content -Raw | Set-Content` 会吃掉 `"""`、造出 SyntaxError）；改用编辑器/`write`。
7. **量退出码**：`& python ... > $null` 量不到真退出码，要 `Start-Process -Wait -PassThru -RedirectStandardOutput` 读 `$p.ExitCode`；另 cuDNN 参与 LSTM 时进程会以 `-1073740791`（`0xC0000409`）退出，修法见 `textrec/README.md` §7。
8. **`drop_last=True`**：`--limit < --batch` 时一个 batch 都不跑（会得到假结论）。
9. **判据先写死再跑**：本项目的每一次"反向证伪"都靠这条（§5.143 的 +4.1pp 就是冻结判据抓出来的）。
10. **`--cases` 收的是案例号、不是 split 名**：`tools/eval/gt_retest.py --cases 10GT` 会把 `10GT` 当成一个案例号 ⇒ **只跑 case 10**（1 张的均值），指纹逐案表还会报 `10GT=MISSING`，看起来像大盘崩塌（实测把 76.50 误当回归）。默认留空 = 官方 10 张。
