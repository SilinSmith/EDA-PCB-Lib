## 0. 一句话结论

- 可用数据 = **48 组 `case*`**（`新补充训练集(1)` 里）；`dataset/` 的 34 组与它**逐字节重复**。
- 另外 **10 组非 `case` 前缀**（`SCH_*`）按同事口径**不用**；它们的坐标系又是另一套（归一化）。
- 坐标系是**新标准**：`case*` 用**像素单位 + 原点在左下（Y 向上）**，与交付图片像素帧差一个**上下翻转**——
  `y_img = H - y_label`，`x` 不变，**没有缩放**。全量 48/48 页验证通过。
- 标签里**没有文字框**，只有「元件符号框 + 引脚点」。做 CRNN 要用弱配对猜框，**标签纯度约 56%**，
  直接拿去训练会带噪（见第 7 节）。训练可跑通（第 8 节）。

## 3. 标签格式（页面级 GT，非框级）

顶层只有三个键：`components` / `pins` / `nets`，**没有画布宽高、没有 imagesize 字段**。
下面是 `dataset\case_0001.json` 的真样例（截断到 40 行）：

```json
{
  "components": {
    "U2": { "Name": "GAS-1", "type": "box", "value": null,
            "bbox": [471, 1157, 669, 1237] },
    "R5": { "Name": "R5", "type": "r", "value": "3R",
            "bbox": [768, 1207, 807, 1227] }
  },
  "pins": {
    "R5": {
      "pin_1": { "pinname": "1", "point": { "x": 748, "y": 1217 } },
      "pin_2": { "pinname": "2", "point": { "x": 827, "y": 1217 } }
    }
  },
  "nets": {
    "net_1": {
      "hyperGraph": "(C7.1,R8.1,U2.3,...)",
      "edges": { "edge_1": [ {"x": 748, "y": 1177}, {"x": 728, "y": 1177} ],
                 "edge_2": [ {"x": 728, "y": 1177}, {"x": 728, "y": 1167} ] }
    }
  }
}
```

| 路径 | 含义 | 备注 |
|---|---|---|
| `components.<位号>.Name` | 器件型号/名 | 位号本身通常是**键**（`R5`），`U2` 的 Name 是 `GAS-1` |
| `components.<位号>.type` | 符号类型 | `r` / `c` / `box` / 电源符号等 |
| `components.<位号>.value` | 值文本 | 可为 `null`（如 U2）；实数如 `3R`、`10k`、`100nF` |
| `components.<位号>.bbox` | **符号体的外接框**（不是文字框！） | `[x0,y0,x1,y1]`，原点左下 |
| `pins.<位号>.pin_N.pinname` | 引脚名 | 引脚号是键 `pin_N` 的 `N` |
| `pins.<位号>.pin_N.point` | 引脚端点 | `{x,y}`，原点左下 |
| `nets.<net>.hyperGraph` | 该网络的端点集合（字符串） | 仅核对用 |
| `nets.<net>.edges.edge_N` | 折线段的两个端点 | `[{x,y},{x,y}]`，原点左下 |

单页规模示例：`case_0001` = 130 元件 / 278 引脚 / 61 网络 / 222 折线段；
`新补充训练集(1)\02\SCH_Schematic1_1-P1…` = 61 / 115 / 19 / 106。

## 5. 坐标系体检（关键）

判据：把 `nets.edges` 折线栅格化后，量「折线像素落在**绿色导线**上的比例」。
绿线是 KiCad 导线色，全图占比（基线）只有 0.002–0.014；所以命中率 ≫ 基线的假设才成立。

| 假设 | `case_0001` 2782×1683 | `case_0012` 4698×3326 | `case_0024` 1241×595 | `case_0029` 4698×3361 | `case_0060` 2362×1672 |
|---|---:|---:|---:|---:|---:|
| (a) 原样像素（y 向下） | 0.015 | 0.032 | 0.125 | 0.001 | 0.037 |
| (b) 缩放 `W/1600`、`W/2560`、`W/2362` | 0.00–0.03 | 0.00–0.04 | ≤0.16 | 0.00 | ≤0.25 |
| (c1) 归一化 `[0,1]*W,H` | 越界 | 越界 | 越界 | 越界 | 越界 |
| **(d) 像素 + Y 翻转 `y'=H-y`** | **0.689** | **0.782** | **0.756** | **0.805** | **0.689** |

- **48/48 组 `case*` 全部命中 (d)**：命中率 0.656–0.805（中位 0.756），最佳 dy 偏移在 48 页上**全是 0**
  → `y_img = H - y_label` 精确成立，`x` 不变，**不需要任何缩放**（双尺度检测率、1600/2560 假设全部被否）。
- 10 组 `SCH_*` 是另一套：`x'=x*W, y'=y*H`（**归一化、原点左上、不翻转**）命中 0.696 / 0.747，
  翻转反而塌到 0.02–0.03。→ 两种口径混在同一个交付里，**按文件名前缀分流是必须的**。
- 视觉证据（PIL 叠加后 1:1 与原图对照）：
  - `eda-pcb\work\_newdata_check\FIXED_dataset_case_0001.png`：翻转后品红折线**压在绿色导线上**，
    红框套住元件符号，蓝圈落在引脚端点；翻转前（`dataset_case_0001.png`）折线整体漂到文字和空白处。
  - `eda-pcb\work\_newdata_check\FIXED_sub1_case_0060.png`：同上，四个 U5–U8 组的导线全部对齐。
  - `eda-pcb\work\_newdata_check\ZOOM_ds_case0001.png`（3× 放大）：红框 = 电阻/电容**符号体**，
    位号 `R5` 印在框外左上、值 `3R` 在框外右上；蓝圈正好在引脚末端。
    → **`components.bbox` 不是位号文字框**，不能直接当 CRNN 的框用。

## 6. 坑清单（都会影响训练/训练集构建）

1. **`bbox` 是符号体，不是文字框**。交付里没有任何「文字在哪」的信息 → 只能弱配对猜框。
2. **Y 轴翻转**，y 向下直接用会整体错位（且错位不是平移能救的）。
3. **两套坐标口径**（像素/翻转 vs 归一化/不翻转）混在一个目录里。
4. **重复**：`dataset` 的 34 组与 `新补充训练集(1)` 逐字节相同，不去重会重复计权。
5. **文件名与内容不对应**（`case_0002` 的内容存在 `03\case_0003.json`）→ 不要用文件名当 ID，
   要用目录内文件名或内容哈希。
6. **字符表外字符**：11 条记录的值是 `33Ω` / `1KΩ` 这种带 `Ω` 的，
   `textrec/data/charset.json`（67 类）里没有 `Ω` → 训练时会被「丢弃未知字符」判掉。
7. `pinname` 字段信息量很大（`HEAT_P`、`CCP0_3/P2_5`、`SPI_MISO`…），但**没有被转成任何 role**；
   `net_label` / `note` 也没有数据来源。6 个 role 里只有 3 个能落地。
8. 尺寸跨度大（1241×595–4698×3361），同一清单里文字高度 5–41 px，p90=20 px。
