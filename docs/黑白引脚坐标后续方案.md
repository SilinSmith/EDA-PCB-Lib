# 黑白引脚最终坐标：定义、证据与后续实施方案

状态：2026-10-09 的调查与实施建议。坐标估计尚未落地，本轮框边证据改动没有移动原引脚候选坐标。

## 最终应该输出哪个点

赛题指南附录三区分两个位置：base 是引脚接入元件本体框的位置，tip 是引脚外端、电气连接的位置。提交 JSON 的 `point` 应是 tip。框内名称匹配可以用 base，不能因此把 base 作为最终坐标，也不能把远处导线的折弯、分叉当作 tip。

本文引用的是已保存的赛题指南与官方 QA，未在本轮实时刷新线上文档。QA 的 A4 明确说并不保证红绿区分，还会出现黑色图；没有补充同色、同宽、共线时从像素唯一定位交界的规则。QA 的 A10 要求正式评测以官方10版本为准，A20 承认公开训练标注存在误差。

## 为什么不能保证仅凭像素找出交界

同色、同宽的引脚和导线接成直线时，tip 处可以没有颜色、宽度或形状变化。能够找到 base、方向和所属元件，不代表能够唯一观测 tip。此时需要额外的视觉符号模板、原始符号几何或经核验的训练监督。

已公开诊断例 `0015-Datasheet / U1.pin_1 / TS`：GT 为 `(268,439)`，换为图像坐标是 `(268,82)`；可见右框边约 x=262，黑线连续到约 x=310 才折弯，GT 所在 x=268 没有可见分界。当前固定向外12像素的输出为 `(273.7,438.5)`，欧氏误差约5.72像素，超过默认5像素容差。该例用于解释不可观测性，不用于在验证标注上拟合长度。

另外，同图 U3 的部分悬空短线，其公开 GT 也没有落在可见自由端。可见自由端提供视觉端点候选，但必须先核对该符号样式的标注约定。不能据此推导赛题要求取短线内部的任意一点。

## 推荐实施顺序

1. 内部分别保存 `base`、朝外方向、`tip`、坐标来源和不确定性；最终 JSON 仍严格使用赛题规定字段，不添加诊断字段。
2. 有颜色、宽度变化或可靠自由端时，提取视觉 tip 候选，并用开发样例核对标注约定。
3. 连续同色线没有可见分界时，匹配同一视觉符号模板和图像尺度。有同一元件上经核验的可靠端点时，用它校准。芯片型号或电气引脚库可以辅助名称与编号，但不能单独证明图形引脚长度。
4. 模板/可靠端点不足时，训练沿引脚方向的长度估计。输入可包括元件裁图、框边接入点、方向、线宽、字体尺度、引脚间距与样式特征；使用已核验开发标注监督，避免把公开标注异常直接学成规则。
5. 用 `tip = base + length * outward_direction` 得到候选，再投影到该引脚线的中心。图像内部采用左上角坐标；导出时沿用现有提交格式的坐标转换。YOLO归一化训练坐标与最终赛题 `point` 不混用。

不建议对整张图统一使用一个固定长度，也不建议直接设“引脚长度等于字体高度”或“等于半个引脚间距”：目前没有足够证据支持通用比例，同图不同符号也可以使用不同长度。

## 验证标准

分别报告可见端点、模板估计、缺少模板的同色连续线，以及疑似标注不一致的样例。先固定开发数据、参数与代码，再评估固定的公开验证样例；这些都是公开训练图，可能与原模型训练重叠，不属于官方隐藏测试。

至少报告坐标误差分布、5像素命中率、引脚名称和身份是否正确，以及最终完整解析得分。模板估计或学习得到的 tip 应标明为估计，不能宣称直接检测到了不存在的像素分界。
