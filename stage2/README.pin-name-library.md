# IC 引脚名称库

名称库只在引脚归属和编号读取结束后处理已有名称。它没有图片编号、芯片型号、标准引脚顺序或参考答案。标准 JSON 中仍只有比赛要求的字段；纠正依据保存在阶段二的 `_assigned/<case>.json`，不会写进比赛 JSON。

## 内容与用法

`pin_name_library.json` 保存常见电源、控制、SPI、I²C、UART、调试、时钟、模拟、USB 和数据引脚名称，以及 GPIO、端口、通道和总线的数字后缀格式。`pin_name_library.py` 按这些规则提出候选。

默认开启，可用环境变量 `STAGE2_PIN_NAME_LIBRARY=0` 关闭。可直接运行原来的 `python -m stage2.run ...`，不需要新模型、联网或额外依赖。

## 第一版的替换条件

- 已经符合库中格式的原文保留，包括大小写、前导零、复用名称 `/`、低有效符号和下划线。纯数字名称原样保留。
- 只考虑长度相同、明确易混字符的替换：O／0、I／1、B／8。不会增删字符、去掉符号、猜测编号或根据编号顺序补名称。
- GPIO 中的 O／0：原读数置信度至少 0.85，并且同一芯片至少有两个不同的 GPIO 数字名称，且这些原始读数置信度至少 0.90。例如 `GPI016 → GPIO16`，后缀 `16` 保留。
- UART、端口及其他更易歧义的名称，还必须有同一引脚的完整裁片两次实际读成候选，每次置信度至少 0.90。两次读取采用不同白边，并核对当前引脚、框、方向和真实输入哈希。两次视图并非统计独立样本，不能据此把置信度提升为接近 100%。
- 仅因“完整名称字符不一致”而被旧规则保留的裁片可重新判断。裁片截字、跨行、污染、引脚归属不明或编号几何存疑等拒绝原因仍然有效。
- `RXDO` 和 `TXDO` 可能是真实名称。只有上下文和上述裁片证据同时成立时，才改成 `RXD0` 或 `TXD0`。
- 多个库内解释、库外名称或证据不足，保留原文并记录原因。电源名称在本版只做格式识别，避免名称纠正牵动电源网络规则。

## 记录与边界

每次纠正记录原文、输出、候选、字符位置、同芯片原始名称、裁片读数及采纳或拒绝理由。原 OCR 候选记录保持不变；名称的 `conf` 仍代表原始 OCR 的置信度，不能当成纠正后的正确率。

名称纠正前会冻结重复编号排序用的旧名称。它不会重新选择编号、引脚坐标、所属芯片、位号或网络。后续纠正不能把本轮新改出的名称当成证据，避免误改连续传播。

名称库无法补救引脚漏检、文字框不完整、编号错误或严重模糊。新增规则应先补对应的保护测试，再实际推理和逐行回归；不要仅按训练图的期望字符串添加特例。
